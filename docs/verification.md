## 산출물 정리·1.2.1 테스트 앱 연결 — 2026-10-08

사용자 요청으로 최신·직전본 보관 기준을 적용했다. 오래된 빌드 20개·검증 폴더 60개·설치 파일 보관 버전 4개와 다운로드 캐시를 삭제하고, 보호 자료를 제외한 정리 내역을 [경로·해시·용량 기록](benchmarks/release-cleanup-20261008.json)에 남겼다. `build/`·`dist/`·`release/` 합계는 약 **13.14GiB에서 4.35GiB로 8.79GiB 감소**했다. 실제 앱은 기존 26개에서 최신 앱 1개를 추가하고 과거 20개를 지워 **7개**가 남았다.

일반 앱은 최근 검증 2개이며 나머지는 `KEEP.md` 1개·실패 재현 1개·복구 백업 3개다. 실패 또는 혼합 검증 자료와 Rust·GitHub CLI 도구를 유지했다. `build/installer.nsh`와 현재 `dist/`를 보존했고, 설치된 앱이나 사용자 데이터를 변경하지 않았다. 보호 파일 10개와 `KEEP.md` 10개의 해시가 정리 전후 일치한다. 삭제 직전 관련 앱·빌드 실행과 Passport DMG 마운트가 없음을 확인했다.

Mac 공개 1.2.1 DMG에서 앱을 한 번 추출해 `codesign --verify --deep --strict`와 별도 임시 프로필의 숨김 smoke를 통과했다. 버전 1.2.1·arm64, 실제 로컬 PTY·helper·초기 DB·정상 종료 코드 0을 확인했다. launch/창/exit/종료 감사 각 1회, 표시·네이티브 포커스 0회다. 검증 후 `release/builds/Passport.app` 상대 링크를 이 앱으로 갱신했다. 전체 빌드·E2E와 데스크톱 검사는 반복하지 않았다.

직전 공개 Mac 1.2.0 설치 파일을 내려받아 공개 체크섬과 `68a5b0d3fc8c8d054d26afcce51d6bdbb2ff54fac235ceb9e147fc3222ebc7a1` 일치를 확인했다. 최신 1.2.1 원본 receipt의 증거 파일·DMG 해시도 그대로다. Windows 후속 배포 상태는 변경하지 않았다. 아래 과거 경로는 당시 기록이며 삭제된 로컬 자료는 이번 정리 목록에서 확인한다.

## 동작 버튼 스타일 통일과 Mac 테스트 앱 — 2026-10-08

아이콘·텍스트 버튼과 작업 도구의 투명 배경·테두리 제거 규칙, 새 탭 버튼의 점선 테두리를 없애 일반 동작 버튼의 공통 스타일을 사용하도록 정리했다. 단축키의 `키 변경`·X·`초기화`는 높이 34px, 테두리 1px, 모서리 6px와 동일한 테마 배경색을 사용한다. 탭·메뉴·주요 동작·위험 동작의 의미를 나타내는 상태 스타일은 유지한다.

## 단축키·간격 수정본의 Mac 테스트 앱 — 2026-10-08

아래 수정 내용을 포함한 `ea2ffc0` 작업 사본을 Apple Silicon용 Passport 1.2.0 앱으로 패키징했다. `codesign --verify --deep --strict`를 통과했고, 패키지의 main·preload·renderer JS/CSS 해시가 앞서 검증한 소스 빌드와 일치한다. 격리된 임시 데이터로 실제 PTY·내장 helper·초기 DB·renderer Node 접근 차단·종료 코드 0을 확인했다.

패키지의 단축키·업데이트·사용성 숨김 GUI **16개가 실패·생략·재시도 없이 통과**했다. 다크·라이트와 세 창 크기의 설정 화면을 포함한다. smoke와 GUI를 합쳐 launch/exit/정상 종료 감사는 각 4회이며 **창 표시·네이티브 포커스는 0회**다. 관련 부분 검사 결과이며 전체 배포 승인이나 Windows 실기·데스크톱 검사 완료를 의미하지 않는다.

## 단축키 단일 지정과 공통 UI 간격 — 2026-10-08

`ea2ffc0` 작업 사본에서 기능당 키 하나로 변경·해제·초기화하도록 수정했다. 기존 문서·백업·가져오기는 두 OS의 첫 번째 키만 유지하고 빈 배열은 보존한다. 저장 형식과 IPC는 유지하며, 편집 가능한 기본 키와 xterm·Chromium·메뉴의 기본 동작 차단 키를 분리했다. 키 표시는 테두리 없는 텍스트로, X는 아이콘 버튼으로 표시한다.

제목과 버튼의 정렬, 글꼴 라벨의 중복 여백, 업데이트·테마·알림·가져오기·시작 화면의 붙은 안내문, 포트 포워딩·시작 프로파일 대화상자의 간격과 알림함 빈 화면을 수정했다. 레이아웃 회귀는 가로 넘침 외에 실제 간격·중앙 정렬·버튼 높이·중첩 테두리도 판정한다.

| 검사 | 결과 |
| --- | --- |
| 타입·단위/통합 | 175 통과·8 조건부 생략(Windows 전용 4, FTP/FTPS 2, Docker 1, 파일 부하 1) |
| 배포 정책·회귀 | 73 통과 |
| Rust helper·앱 빌드 | 기존 격리 Rust 도구 체인을 지정해 통과 |
| 관련 소스 숨김 GUI | 30 통과, 실패·생략·재시도 없음 |

일반 E2E는 창을 처음부터 숨기고 포커스를 비활성화한다. 추가 창, 작업 탭 이동, 알림 열기와 두 번째 인스턴스 요청에도 같은 정책을 적용한다. 창을 확인할 때는 `npm run test:e2e:show`로 비활성 상태로 표시하고, OS 포커스·클립보드 검사는 `npm run test:e2e:desktop`으로 명시적으로 실행한다. 기존 일반 앱의 창 동작과 사용자 설치본은 유지했다. 숨김 모드를 지원하지 않는 과거 빌드는 실행 전에 거부한다.

Mac ARM64에서 기본 숨김 GUI **47개 통과·9개 조건부 생략**을 확인했다. Windows 전용 6개와 선택 Docker·장시간 부하 3개를 생략했으며 네이티브 데스크톱 검사 3개는 별도 명령으로 분리되어 이 수에 포함하지 않는다. 터미널 키 입력·SSH/SFTP·파일·설정·테마·스크롤·추가 창 이동·PTY 종료를 포함한다. 숨김 앱의 종료마다 네이티브 창 표시·포커스 이벤트가 모두 0인지 검사했다. 별도 회귀에서도 내부 창 2개 생성·표시 0회·포커스 0회를 확인했다.

‘창만 표시’ 모드의 입력·추가 창 이동·두 번째 인스턴스 시나리오 **1개 통과**에서 창 2개 표시·포커스 0회와 두 창의 `focusable: false`를 확인했다. 빌드·타입 검사, 창 정책 단위 **2개**, 배포·중단 보호 회귀 **36개**도 통과했다. 네이티브 포커스 검사가 빠진 기록의 게시 거부, 기본 숨김 모드와 잘못된 모드의 거절, 창 표시·포커스 침범 시 테스트 실패를 포함한다. `--desktop` 없는 정식 배포 검증도 앱을 열기 전에 거부한다.

추가한 Windows 셸별 검사에서 실제 cmd 오류 2개도 발견해 수정했다. node-pty의 argv 이스케이프가 시작 파일의 따옴표에 역슬래시를 추가해 실행을 막았고, Rust의 argv 이스케이프는 DOSKEY 매크로 이름과 명령에 따옴표를 그대로 등록했다. 각 프로그램이 해석하는 원래 명령줄을 전달하도록 수정했다. 내장 Bash·cmd·Windows PowerShell에서 한글·공백·특수문자가 있는 PATH, 환경 변수, 단축 명령과 실제 키보드 입력을 통과했다.

로컬 검증에는 작업 폴더에 격리한 Rust GNU helper와 고정된 Node-API 네이티브 바이너리를 사용했다. 공개 Windows 릴리즈는 별도 MSVC CI 빌드에서 패키지 검증을 통과한 경우에만 게시한다. 최종 설치·패키지·공개 파일 검증 결과는 위 공개 배포 기록에 보관한다. 실제 AI 서비스 요청과 OS 배너 표시를 이번 자동 검사로 확인했다고 주장하지 않는다.

동일한 로컬 패키지의 전체 GUI도 **54개 통과·4개 생략**했고, 배포할 dist 파일 65개와 app.asar 내용 일치·x64 앱/helper/Bash·렌더러 격리·정상 종료를 확인했다. 시험 EXE의 현재 사용자 전용 설치·실제 DPAPI·셸·시작 시 공개 업데이트 확인·제거를 통과했으며 설치된 페이로드가 빌드와 같고 제거 후 레지스트리가 남지 않았다. [로컬 Windows 검증·해시 기록](benchmarks/verification-windows-v1.1.0.json).

[첫 Windows 추가 게시 실행](https://github.com/poyal/passport/actions/runs/36859824420)은 기본 검사·패키지 smoke·설치 범위·기존 GUI 51개를 통과했지만 신규 셸 검사 4개에서 PATH 확인이 실패해 게시를 건너뛰었다. 네 셸의 초기화·환경 변수·단축 명령은 통과했으나 긴 runner PATH가 검증할 앞부분을 화면 밖으로 밀었다. 첫 PATH 항목만 출력하도록 검사하고, 로컬 패키지에 긴 PATH를 전달한 셸 검사 **3개 통과·PowerShell 7 생략**으로 재검증했다.

[두 번째 실행](https://github.com/poyal/passport/actions/runs/36861988367)은 네 셸을 포함한 GUI **54개 통과·3개 생략** 후 드라이브 루트 검사에서 실패해 게시하지 않았다. 보호된 `C:\DumpStack.log.tmp`의 `lstat`가 runner에서 `EINVAL`을 반환해 전체 파일 목록 조회가 중단됐다. 목록 탐색에서는 해당 항목을 생략하고, 명시적 파일 접근과 재귀 전송은 오류를 유지하도록 수정했다. 접근 가능한 형제 항목 표시와 엄격한 전송 열거를 회귀 검사에 추가했다.

이 수정 후 기본 검사 **114개 통과·4개 생략**, 실제 Windows 드라이브 루트 GUI **3회 통과**를 확인했다. 이전 로컬 설치본의 112개 결과는 그대로 보관하고, 파일 탐색 수정이 포함된 새 CI 설치본과 구분한다.

[세 번째 실행](https://github.com/poyal/passport/actions/runs/36864037203)은 기본 검사 114개·빌드·EXE·설치 범위까지 통과했지만 패키지 smoke가 45초 제한 뒤에도 종료되지 않아 취소했다. 전체 GUI와 게시 단계는 실행하지 않았다. smoke 제한 초과 시 시험이 만든 프로세스 트리를 종료하고 반드시 실패를 반환하도록 보완했다. 실패 로그에는 중단 단계를 추가했고, Windows CI는 첫 smoke 명령의 종료 코드를 확인해 실패 시 뒤의 GUI와 게시를 진행하지 않는다.

보완 후 실제 로컬 패키지의 smoke를 통과했고, 별도 복사본의 제한을 0.6초로 줄인 시험에서 약 1.02초 안에 실패 코드 1과 시험 프로세스 트리 종료를 확인했다. 이 제한 시간 보완에서는 제품의 일반 실행·종료 경로를 변경하지 않았다.

[네 번째 실행](https://github.com/poyal/passport/actions/runs/36867262927)은 기본 검사·빌드·설치 범위 뒤 smoke의 PTY 명령 출력 대기에서 실패해 전체 GUI와 게시를 실행하지 않았다. 백엔드 초기화 완료와 실제 UI·대화형 프롬프트 준비를 구분하도록 입력 검사를 보완했다. 세션 이벤트를 5초 지연하면 기존 검사가 명령을 너무 일찍 보내 실패하는 것을 로컬에서도 재현했다. 실제 연결 표시·셸 프롬프트·창 포커스와 렌더링 완료 뒤 키보드 명령을 한 번 보내 결과를 확인한다.

재현 중 별도의 Windows 종료 문제도 확인했다. node-pty 1.1.0은 내장 ConPTY 종료 뒤 추가 출력이 있어야 worker 정리를 시작해 조용한 PTY에서 종료 완료가 오지 않을 수 있었다. [배치 스크립트](../scripts/prepare-node-pty.mjs)가 출력 배출 대기를 유지하며 정리를 항상 시작하도록 소스 의존성과 패키지를 보완한다. 버전·원본 코드가 바뀌면 검토 없이 적용하지 않는다.

네 개의 조용한 실제 Windows PTY를 종료하는 회귀를 포함해 기본 검사 **115개 통과·4개 생략**을 확인했다. 별도로 만든 로컬 패키지의 실행·PTY·격리·정상 종료 **3회 통과**, 5초 지연 이벤트 재현 **1회 통과**와 새 프롬프트·키 입력 조건을 적용한 셸 검사 **3개 통과·PowerShell 7 생략**을 확인했다. 기존 GNU-helper NSIS 설치본은 변경하지 않고 이 종료 보완이 포함된 새 앱과 구분해 보관한다.

후속 CI에서는 패키지 실행과 500개 호스트 목록의 모든 스크롤 검사가 통과했지만 `afterAll`의 앱 종료 대기가 만료됐다. GUI 종료 검사는 정상 `app.quit()` 요청 뒤 실제 종료 코드 0을 기다린 다음 Playwright 디버거 연결을 해제하도록 보완했다. 여러 창·500개 호스트 시나리오 **18개 반복 통과**, 최종 로컬 패키지 전체 GUI **54개 통과·4개 생략**과 dist 파일 **65개 일치**를 확인했다. 앞선 혼합 Bash 알림 시험의 간헐적인 첫 합성 입력 누락, 폐기한 검사 수정, GUI를 제외한 네이티브 크기 변경·입력 **20회 통과** 자료도 [후속 검증 기록](benchmarks/verification-windows-v1.1.0.json)에 함께 보존한다. 공개 MSVC 설치본의 실행 결과는 별도로 기록한다.

## 그룹 드래그 제한과 중첩 분할 여백 수정 — 2026-10-01

여러 패널로 묶인 탭 전체를 다른 탭 안에 드롭하는 동작을 차단했다. 사이드바 탭 순서 변경과 묶인 탭 안의 개별 패널 이동은 유지한다. 드래그 표시뿐 아니라 실제 배치 변경에서도 검사하며, 대상이 사라진 경우 원본 패널을 제거하지 않는다. 탭 내부의 템플릿 저장은 아이콘으로 표시하고 접근성 이름·툴팁을 유지한다.

중첩 그리드에서 `0.5fr` 트랙이 최소 너비에 걸리면 남는 공간을 채우지 않는 문제를 재현했다. 1240px 영역에서 320+5+645px만 사용했으나 비율을 50fr 단위로 환산한 뒤 590+5+645px로 영역을 채웠다. 가로·세로 중첩 분할 모두 경계 측정과 화면 검토를 통과했다.

## AI 알림 수신 재점검 — 2026-10-01

## 1.0.0 설정 재구성·자동 OS 아이콘·파일 색상 — 2026-09-30

동작 검증은 0.3.4 후보 빌드에서 수행했다. 사용자 요청으로 런타임 소스 변경 없이 배포 메타데이터를 1.0.0으로 승격한 뒤 최종 설치본을 별도로 검증했다.

외형은 앱·터미널·테마·사용자 테마, 인증은 프로필·호스트 키, 데이터 관리는 내보내기·가져오기·자동 백업, 세션 로그는 조회·보관 설정으로 나눴다. 카드의 고정 최대 폭을 제거하고 입력·목록·버튼 간격과 반응형 배치를 통일했다. 탭 전환 시 입력 초안 유지, 방향키·Home·End·연결된 tabpanel을 확인했다.

아이콘을 선택하지 않으면 호스트 이름에서 CentOS·RHEL·Rocky 등을 추정하고 접속 후 감지 결과를 우선한다. 사용자가 지정한 아이콘은 이후 OS 감지에도 유지한다. 이전 데이터의 일반 Linux 아이콘은 자동으로 이전하며 새로 사용자가 선택한 Linux는 고정된다. 사용자 원본 DB와 인증 정보를 시험에 사용하지 않았다.

창 이동 뒤 이전 창의 지연 resize·ack만 무시하고 입력·종료·명령의 소유권 검사는 유지한다. 실행 중인 SSH 분할 탭을 다른 창으로 옮기고 되돌릴 때 연결·스크롤 기록 유지와 이전 창의 입력 차단을 확인했다. 앱 종료·재실행에서는 탭·분할 배치를 복원하고 연결은 끊긴 상태로 시작하며 명시적 연결 후 정상 동작한다.

## 0.3.3 구형 SSH 자동 호환·옵션 제거 — 2026-09-30

사용자 요청에 따라 SHA-1 group14·GEX·group1을 모든 SSH·SFTP·터널 연결에서 현대 기본 목록 뒤에 추가한다. 호스트의 **SSH 알고리즘** 옵션과 `legacySSH` 필드를 제거했다. 이전 데이터의 `legacySSH: false`도 파싱 시 제외하므로 호스트를 다시 저장하지 않아도 자동 호환이 적용된다. 현대 방식과 구형 방식을 모두 제공하는 시험 서버에서는 `curve25519-sha256`이 선택됐다. 잘못된 비밀번호와 변경된 지문은 계속 거절한다.

## 0.3.2 구형 SSH 호환·지문 확인 설정 — 2026-09-30

사용자가 보고한 `no matching key exchange algorithm`을 SHA-1 전용 localhost 서버에서 재현했다. 호스트의 **SSH 알고리즘 → 구형 서버 호환 · CentOS 5/6**을 켜면 SHA-1 group14·GEX·group1을 기본 목록 뒤에 추가한다. 기본값과 현대 방식 우선순위는 유지하며 해당 호스트의 SSH·SFTP·터널에 함께 적용한다.

Electron 44.4.5의 BoringSSL에서는 이름 기반 `modp2`가 없어 group1을 추가해도 `Unknown DH group`이 발생했다. ssh2 1.17.0의 해당 그룹에 RFC 2409 §6.2의 동일한 소수를 명시하도록 수정했다. 설치·빌드·단위 시험에서 멱등적으로 적용하며 대상 버전이나 코드가 달라지면 중단한다. 전역 crypto API는 변경하지 않는다. 설치본의 수정된 ssh2 파일이 로컬 패치 파일과 일치함도 확인했다.

**설정 → 인증 프로필 → SSH 호스트 키 → 첫 연결 지문 확인창 표시**를 끄면 첫 지문을 자동 등록한다. 기본은 확인창 표시이며, 이미 등록된 지문이 바뀌면 설정과 관계없이 차단한다. 기본/호환 모드, 현대 방식 우선 선택, 잘못된 비밀번호, 지문 변경 차단을 시험했다.

- 타입·빌드·형식 검사 통과. 단위/프로토콜 통합 **58개 통과**, 선택 실행 2개 제외.
- 전체 GUI **20개 통과**, 선택 10분 부하 1개 제외. 마지막 버전 표시 수정 후 사용성 GUI 6개와 최종 설치본의 구형 연결 GUI 1개가 통과했다.
- 실제 Docker OpenSSH **8개 구성 통과**: 기존 6개 OS와 CentOS 7/OpenSSH 7.4의 group1·SHA-1 GEX 전용 구성 2개. 비밀번호·암호화 키·잘못된 비밀번호 거절·지문 변경 차단·sh/bash/zsh·한글·PTY·환경·1MiB SFTP 왕복 SHA-256·원격 간 전송·권한·로컬/원격/SOCKS5 터널을 확인했다. 구형 전용 구성에서 기본 모드가 연결을 거절하는 것도 확인했다. 시험 컨테이너는 모두 정리했다. [원시 결과](benchmarks/docker-ssh-v0.3.2.json).
- 최종 설치본에서 group1 SSH 터미널·한글 입력·SFTP, 첫 지문 확인창 없이 연결, 설정 저장 유지, 실제 앱 버전 표시와 정상 종료를 확인했다.
- 설치본의 로컬 PTY 실행·렌더러 Node 접근 차단·종료 코드 0 검증 통과. main·preload·renderer·패치된 ssh2의 패키지 내부 SHA-256이 최종 빌드와 일치했다. [실행 결과](benchmarks/packaged-smoke-v0.3.2.json).

사용자가 지정한 CentOS 5.11 서버에는 인증·명령 없이 협상 정보만 조회했으나 시간 초과가 발생했다. 실제 서버의 알고리즘과 로그인은 확인하지 못했다. 위 구형 구성은 CentOS 7에서 해당 알고리즘만 허용한 시험이며 실제 CentOS 5/6 OS 시험과 구분한다. 0.3.1의 10분 부하·4GiB 전송을 이번 버전의 시험 결과로 재사용하지 않는다.

[Electron의 safeStorage 서명 안내](https://github.com/electron/electron/blob/v44.4.5/docs/api/safe-storage.md), [Apple의 키체인 접근 안내](https://support.apple.com/guide/keychain-access/if-youre-asked-for-access-to-your-keychain-kyca1243/mac). 실제 사용자 키체인은 읽거나 수정하지 않았고 자동 GUI는 모의 vault를 사용했다.

## 자동 검증

- 타입·단위/통합: 기존 분할·전송·내보내기·인증 검증에 그룹 상속, 변수 치환, 단축키 충돌, 로그의 청크 경계 검색·보관 한도·북마크·내보내기, 실제 로컬 PTY, 자동 재접속 시 시작 명령 미반복, v0.1 DB 승격 검증을 추가했다.
- Electron GUI: 호스트·SSH·분할·파일·시작 시 키체인 미호출에 더해 동시 키 입력과 장치 응답 구분, 탭 변경 시 해제, 명령 실행·이력, 로그 기록, 실제 로컬 셸, 사용자 테마·단축키·출력 강조, 체크한 필드만 일괄 편집을 확인했다.
- 별도 창: 연결된 2분할을 새 창으로 옮기고 원래 창으로 복귀시켰다. SSH 연결 수가 2개로 유지되고 이전 출력과 이후 입력이 보존되며 원래 창의 잘못된 대상 입력은 거절되는 것을 확인했다.
- 새 탭 표시: 저장 응답이 창 소유 정보 이벤트보다 먼저 도착하면 새 로컬 터미널이 호스트 화면으로 되돌아가는 경쟁 상태를 수정했다. 저장 직후 문서와 소유 정보를 함께 갱신하고, GUI 시험에서 해당 이벤트를 250ms 지연시켜도 새 탭이 유지되고 명령 실행이 되는 것을 확인했다.
- 일괄 편집 화면: 항목 간 22px, 체크박스와 입력칸 사이 10px로 정리하고 미선택 필드를 비활성화했다. 실제 GUI와 스크린샷으로 확인했다.
- 스크롤: 1024×680 창에서 500개 호스트 목록의 마지막 항목과 펼친 호스트 설정의 하단 저장 버튼까지 각각 휠로 이동함을 확인했다. 선택한 호스트가 목록 밖으로 넘치지 않으며 일괄 편집 도구는 목록 위에 고정된다.
- 파일 목록: 긴 목록이 전송 대기열을 덮던 grid 최소 높이 문제를 수정했다. 100개 파일로 1024×680·1440×900 창, 대기열 접기/펼치기, 좌우 독립 휠 스크롤, 마지막 파일의 우클릭 메뉴 접근을 검증했다.
- 색상 깜박임: 출력 강조를 지웠다 다시 붙이는 처리를 바꾸고, 변경되지 않은 강조 DOM이 이후 출력에서도 유지됨을 검증했다. ANSI 지정 색상 우선과 대체 화면 강조 제외도 확인했다. xterm 6의 이전 viewport 배경이 마지막 행 아래에 검은 띠로 남던 부분도 투명 처리하여 패널 테마 배경을 표시한다.

최종 타입·단위/통합 실행은 **44개 통과, 2개 선택 실행 시험 제외**이다. GUI는 **고유 시나리오 13개를 통과**했다. 마지막 파일·테마 배경·새 탭 경쟁 상태 수정 후 관련 GUI 10개도 통과했다(10분 부하 시험 별도). 단위/통합의 제외 항목은 Docker 매트릭스와 대용량 파일 시험으로 아래에서 별도 수행한다. FTP/FTPS 시험은 Python 환경을 지정해 포함했다.

### Electron 종료 충돌 수정

사용자 보고서의 `ARM-64 (Native)`, `pty.node → ThreadSafeFunction::CallJS → Environment::CleanupHandles`로부터, 로컬 셸의 종료 콜백이 Electron의 Node 환경 해제와 겹친 것으로 판단했다. 동일 경로의 [node-pty 상위 이슈 #904](https://github.com/microsoft/node-pty/issues/904)도 참고했다. 단순 창 닫기 성공만 보던 이전 GUI 검증으로는 SIGABRT를 잡지 못했다.

로컬 셸을 종료 요청한 뒤 실제 종료 콜백 반환까지 기다리고, 이미 닫힌 탭의 콜백도 추적하도록 수정했다. 다시 연결한 패널에 이전 셸의 종료 상태가 전달되지 않도록 했다. Electron 종료 전에 정리가 끝나도록 순서를 바꾸고 모든 GUI/패키지 시험에 프로세스 종료 코드 검사를 추가했다.

4개 PTY의 활성/닫힘/재연결 상태를 각각 3회, **총 9회 반복 실행하여 종료 코드 0, 시그널 없음**을 확인했다. 별도 통합 시험에서는 종료 신호를 무시하는 셸의 강제 종료 대기와 재연결 콜백 구분도 통과했다. 전체 GUI 재실행도 정상 종료했고 신규 macOS 충돌 보고서는 생성되지 않았다.

반복 종료·단위/통합·GUI·패키지 결과의 요약은 [0.3 검증 결과](benchmarks/verification-v0.3.json)에 저장했다.

## 파일 전송 부하

현재 0.3 코드로 4GiB 파일 전송 및 SHA-256 일치, 작은 파일 10,000개 폴더 복사·일부 내용 확인을 통과했다. 시험 시간은 15.11초이며, 대용량 전송 구간의 프로세스 RSS 증가가 512MiB 미만이라는 검증을 통과했다. 두 로컬 파일 어댑터 사이의 스트리밍 시험이므로 WAN SFTP 전송 속도를 의미하지 않는다.

## 터미널 연속 출력

로그·주소 강조를 켠 16분할, 호스트 500개 프로필로 **600.002초** 실행했다. 세션별 100KiB/s 목표로 총 60,835,840바이트씩 전송했으며 평균은 약 99.0KiB/s다. 로컬 IPC/SSH 입력 왕복 지연 **p95 15ms**로 목표 100ms 이내를 통과했다. 전체 앱 프로세스의 working set은 최대 **1,147MiB**, 마지막 표본은 **1,131MiB**였다. 주기적으로 16개 터미널이 활성 화면에 남아 있는지 검사했고 마지막 앱 종료 코드도 0이었다. [원시 결과](benchmarks/terminal-stress.json).

이 수치는 같은 기기의 시험 SSH 서버를 거친 왕복 응답 시간이며 물리 키 입력부터 화면 표시까지의 지연이나 WAN 지연을 별도로 측정한 값은 아니다. 호스트·파일 GUI 검증을 병행한 구간이 포함된다. 출력 강조를 수정하기 전 중단한 실행은 완료 결과에 포함하지 않았다. 이후 마지막 행 아래 배경만 바꾸는 CSS 수정은 별도 GUI 회귀로 확인했다.

## Docker 실제 OpenSSH 매트릭스

모든 시험 컨테이너는 `linux/arm64`, 호스트 포트는 `127.0.0.1`의 임시 포트다. 암호·Ed25519 개인 키는 시험 실행 시 생성한다. 기본 SSH 암호 협상 정책을 완화하지 않았다.

| 서버                           | 결과 |
| ------------------------------ | ---- |
| Alpine 3.22                    | 통과 |
| Ubuntu 24.04                   | 통과 |
| Debian 12                      | 통과 |
| Rocky Linux 9                  | 통과 |
| CentOS Stream 9                | 통과 |
| CentOS 7 AltArch / OpenSSH 7.4 | 통과 |

각 OS에서 비밀번호·암호화 Ed25519 키, 잘못된 비밀번호 거절, 변경된 호스트 지문 거절, sh/bash/zsh 한글 출력, PTY 91×37 변경, 환경 변수, 1MiB 한글 파일의 로컬→SFTP→독립 SFTP→로컬 왕복 SHA-256, chmod 0640을 확인했다. 터널은 로컬·원격·SOCKS5 IPv4/도메인 및 분할된 핸드셰이크를 시험했고 미지원 UDP 요청 거절도 확인했다. [원시 결과](benchmarks/docker-ssh.json).

CentOS 7은 공식 ARM64 아카이브와 이미지 내 ARM64 GPG 키를 사용했다. CentOS 5/6과 모든 구형 SSH 알고리즘까지 지원한다고 의미하지 않는다. 시험 완료 후 해당 실행의 컨테이너만 제거했고 `be-withvtm-postgres`는 실행 상태로 남겨 두었다. 시험 이미지 캐시는 재실행을 위해 보관했다.

## 플랫폼·패키지

Mac은 Apple Silicon 네이티브이며 Rosetta가 필요 없다. Windows x64는 별도 NSIS 스크립트와 네이티브 CI 구성을 제공한다. 이 작업 환경에는 Windows가 없어 실제 Windows 설치·실행 결과는 아직 없다. macOS 최소 버전 목표는 14지만 현재 실측 OS는 27이다. 개인 테스트용 Mac 패키지는 ad-hoc 서명이며 Developer ID 서명·공증은 포함하지 않는다.

생성한 설치본은 `release/Passport-0.3.0-mac-arm64.dmg`이다. 앱 실행 파일의 Mach-O arm64와 `codesign --verify --deep --strict` 통과를 확인했다. 패키징된 앱에서 로컬 PTY 명령 실행, Node 접근 차단, 정상 종료 코드 0까지 확인했다. [패키지 실행 결과](benchmarks/packaged-smoke.json).

DMG SHA-256: `32d3a54712328930a91beeab29d635f235619dd536cf9a2018fa40db34a91d46`.

[워크플로](../.github/workflows/desktop.yml)는 수동 실행이며, 이 작업에서 원격 CI·공개 업로드는 실행하지 않았다.

## 실환경 확인 범위

Windows x64 설치·실행, macOS 14, 두 OS의 실제 한글 IME·배율·네이티브 파일 대화상자·Keychain/DPAPI 보호 흐름은 별도 환경 확인이 남는다. 한글 출력과 키/비밀번호 프로토콜 테스트는 이 OS UI 확인을 대신하지 않는다. 실제 WAN 단절·권한 제한 서버·장시간 원격 대용량 전송도 로컬 시험과 구분한다.
