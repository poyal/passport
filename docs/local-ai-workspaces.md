# 로컬 AI · SSH 작업 공간

Passport의 로컬 터미널·시작 프로파일·AI 알림 안내다. 배포 상태는 [릴리즈 안내](releases/README.md), 실제 시험 결과는 [검증 기록](verification.md)을 확인한다.

미리보기나 새 실행본으로 전환할 때 기존 Passport를 완전히 종료한 뒤 실행한다. 새 로컬 기능은 DB v5·설정 문서 v2를 사용하므로, 이전 실행본을 계속 열어 두면 새 설정을 읽을 수 없다. 현재 실행본끼리는 같은 데이터 폴더의 중복 실행을 막고 기존 창으로 이동한다. 설정 버전을 낮추거나 새 알림 단축키를 삭제할 필요는 없다.

## 사용하기

1. 왼쪽 **+ 새 로컬 터미널**, 새 탭 단축키 또는 시작 화면의 **로컬 터미널**을 누르면 전역 기본 프로젝트 폴더에서 새 로컬 탭을 바로 연다. 기본 폴더가 비어 있으면 홈 폴더를 사용한다. SSH는 **호스트** 화면에서 연결한다.
2. **설정 → 로컬 터미널**에서 기본 셸·시작 프로파일·AI 알림 연동과 적용 순서를 정한다. 열린 로컬 터미널에서 `claude` 또는 `codex`를 입력하면 선택한 셸의 PATH에 설치된 CLI를 실행한다. 설치와 로그인은 사용자가 진행한다.
3. 패널의 **터미널 분할**에서 로컬 AI와 SSH를 함께 배치한다. 작업 목록은 접을 수 있으며 기존 패널·창 이동은 실행 중인 PTY를 유지한다.
4. **설정 → 로컬 터미널**에서 전역 기본 프로젝트 폴더와 시작 프로파일을 정한다. 패널별 직접 선택 → 앱 기본값 순으로 적용한다. 이전 탭별 프로젝트 설정은 기존 패널의 개별 설정으로 이전하며 새 탭에는 전역 기본값만 적용한다. **사용 안 함**은 상위 설정을 상속하지 않는다.
5. 탭을 연 뒤 상단 작업 영역의 **템플릿 저장 아이콘**으로 현재 탭 하나와 그 안의 분할 배치를 저장한다. **템플릿 → 탭 저장**에서도 대상을 선택할 수 있다. 템플릿 카드를 누르면 새 탭 하나를 열고 연결하며, 폴더 아이콘은 **배치만 열기**다. 기존 여러 탭 묶음 템플릿은 업그레이드 및 가져오기에서 제외한다. 앱 재시작·가져오기는 자동 실행하지 않는다.

## 셸과 시작 프로파일

로컬 터미널은 `TERM=xterm-256color`, `COLORTERM=truecolor`를 전달한다. 앱을 실행한 환경의 `NO_COLOR`, `FORCE_COLOR`, `CLICOLOR`, `CLICOLOR_FORCE`는 새 셸에 상속하지 않아 빌드 도구·IDE에서 앱을 시작해도 CLI 색상이 꺼지지 않는다. 사용자가 셸 시작 파일이나 시작 프로파일에서 지정한 값은 이후 적용된다. CLI의 RGB·256색 출력은 그대로 표시하고, 기본 글자·배경과 ANSI 기본 16색은 선택한 터미널 테마를 따른다. [NO_COLOR 동작 규약](https://no-color.org/).

**설정 → 로컬 터미널**에서 기본값과 사용자 프로파일을 관리한다. 여러 프로파일의 순서를 바꾸고 각 항목의 내용을 펼쳐 볼 수 있다. 현재 지원 항목은 명령과 인자를 분리한 단축 명령, 환경 변수, PATH 앞/뒤 추가다. 기본은 기존 값 보존이며, 항목별로 덮어쓰기를 선택할 수 있다. 예약 환경 변수는 직접 변경할 수 없다. 일반 설정에 저장되는 환경 변수에는 비밀번호·토큰을 넣지 않는다.

| OS      | 셸                                                              |
| ------- | --------------------------------------------------------------- |
| macOS   | 계정 기본 셸, zsh, bash                                         |
| Windows | Passport Bash, cmd, Windows PowerShell 5.1, 설치된 PowerShell 7 |

Windows의 새 사용자 기본값은 **Passport Bash + Unix 단축명령**이다. 공식 Portable Git의 셸·Unix 도구를 앱 리소스에 포함하므로 외부 Git Bash나 WSL 설치를 요구하지 않는다. `sh`는 실제 셸이며 `ll`은 단축 명령이다. cmd·PowerShell은 원래 문법을 사용한다. PowerShell 두 버전은 독립 선택이며, 없는 셸로 자동 대체하지 않는다.

프로파일을 사용하지 않는 일반 터미널은 원래 셸의 시작 인자로 연다. 추가 프로파일 또는 AI 실행을 선택한 경우 앱 전용 로더를 사용한다. zsh는 사용자 `ZDOTDIR`과 시작 파일 순서를 이어 읽고 원래 경로를 복구한다. Bash 로더는 `/etc/profile` 다음 첫 사용자 로그인 파일을 읽는 대화형 초기화 방식이며, Bash의 `login_shell` 플래그를 바꾸지는 않는다. 따라서 **추가 프로파일을 켠 Bash에서 `.bash_logout`을 자동 읽는 네이티브 로그인 종료 동작은 제공하지 않는다**. 사용자 EXIT trap은 그대로 유지한다. 그 종료 동작이 필요한 구성은 프로파일을 사용하지 않는 Bash를 선택한다.

PowerShell 로더는 실행 정책을 우회하지 않는다. 정책·사용자 프로파일 오류가 있으면 해당 터미널에 오류가 보이고 적용 실패로 표시한다. cmd 단축 명령은 `doskey`를 사용하므로 대화형 전용이다. cmd는 UNC 시작 폴더와 큰따옴표가 포함된 추가 프로파일 값을 거절한다. 이런 경로나 값은 PowerShell 또는 Passport Bash에서 사용할 수 있다.

패널의 **실행 환경**에서 실제 실행 파일, 폴더, 프로파일 버전, 적용·충돌 생략 결과와 CLI 경로·버전 진단을 확인한다. 변경은 새 세션부터 적용된다. 로컬 자동 로그는 기본적으로 꺼져 있으며 SSH 자동 로그 설정과 별도로 관리한다.

## 파일·폴더 드롭과 줄바꿈

Finder·탐색기의 파일·폴더를 로컬 터미널 본문에 놓으면 파일 복사·붙여넣기처럼 원본 경로를 입력한다. 확장자를 제한하지 않고 빈 파일·폴더도 허용한다. 마우스 아래 패널의 테두리와 안내로 대상을 표시하며, 여러 항목도 기존 입력을 유지하고 Enter 없이 추가한다. 셸에 맞게 인용한 경로를 전달하는 기능이며 CLI 자체 첨부 표시·분석은 CLI에 따른다. SSH 패널에는 파일·폴더 드롭을 지원하지 않는다.

**설정 → 단축키 → 터미널 → 줄바꿈**은 기본 **Shift+Enter**이며 변경·해제할 수 있다. 해당 터미널에 Shift+Enter 신호(CSI-u)를 보내고 일반 Enter는 그대로 둔다. CLI가 이 키를 지원해야 줄바꿈으로 처리한다. 검색·설정의 입력란과 한글 조합 중인 Enter는 가로채지 않는다.

## AI 작업 알림

터미널 간 요청·결과 확인은 알림과 독립적인 [터미널 CLI](terminal-cli.md)를 사용합니다. **CLI 접근**을 켠 새 로컬 터미널에서 `passport identify`, `passport send`, `passport read`를 사용할 수 있습니다. Mac·Windows 1.2.3부터 제공합니다. [플랫폼별 배포 상태](releases/README.md)를 확인하세요.

**설정 → AI 작업 알림**에서 Claude/Codex를 허용하고, 해당 터미널에 **AI 작업 알림** 시작 프로파일을 추가한다. 앱 셸의 실행 래퍼가 호출 단위 설정을 전달한다. 사용자 CLI 설정 파일, 프로젝트 신뢰와 승인 정책은 수정하지 않는다. 절대 경로로 CLI를 직접 실행하면 래퍼를 거치지 않는다.

프로파일을 선택하면 바로 아래에 **Claude/Codex 알림 켜짐·꺼짐**과 각 연동 스위치가 표시된다. 둘 다 꺼져 있으면 프로파일 선택만으로 알림이 연결되지 않는다는 안내를 표시한다. 연동을 켠 뒤에는 새 로컬 터미널에서 CLI를 시작한다. 새 설정은 해당 터미널을 보고 있지 않을 때 배너를 요청하며 기존에 저장한 배너 조건은 유지한다.

- Claude: `Stop`은 **응답 완료**, `Notification.permission_prompt`는 **승인 필요**로 구분한다. `PermissionRequest` 후보 자체는 배너를 만들지 않는다. `AskUserQuestion`·`ExitPlanMode`·MCP 입력 요청은 500ms 동안 합쳐 자동 처리된 요청을 취소하고 **답변 필요**를 알린다. 응답 요청의 식별자가 없으면 일반 **확인 필요**로 표시한다. `StopFailure`와 CLI 오류 종료는 작업 중단을 알리며 도구 실패·정상 종료·사용자 인터럽트는 별도 중단 알림을 만들지 않는다. Stop 신호를 전체 작업 성공으로 판정하지 않는다. 훅은 네이티브 실행 파일과 `args`를 분리한 exec 형식을 사용한다. 이 형식을 지원하는 CLI가 필요하다. [Claude 훅 형식](https://code.claude.com/docs/en/hooks#exec-form-and-shell-form), [설정 병합](https://code.claude.com/docs/en/settings#lists-merge-instead-of-overriding).
- Codex: `notify`의 JSON 인자로 응답 완료를 수신하며 TUI의 승인·계획 질문·비동기 질문 알림은 OSC 9로 받는다. OSC에는 인증된 요청 식별자가 없으므로 **터미널 · 확인 필요**로 표시하고 현재 승인 대기를 단정하지 않는다. OSC 9;4 진행률은 알림에서 제외한다. 기존 notify와 TUI의 알림 설정 세 항목을 각각 보존한다. 상태줄·색상 같은 일반 TUI 설정은 알림 연결을 막지 않는다. 명시적 `--config`/`--profile`/작업 폴더/`--remote` 옵션은 보존하며 연동을 생략할 수 있다. 사용자 훅을 강제로 신뢰시키지 않는다. [공식 알림 설정](https://learn.chatgpt.com/docs/config-file/config-advanced#notifications).
- OSC는 **터미널 · 확인 필요**로 표시한다. 원격 SSH 프로그램도 만들 수 있는 신호이므로 요청자나 실제 승인 대기를 인증한 것으로 취급하지 않는다. 원문은 알림 기록에 저장하지 않는다.

벨 버튼은 모든 창이 공유하는 알림함을 연다. 새 기본 데스크톱 알림은 해당 터미널을 보고 있지 않을 때, 소리와 설명 표시 없이 전달한다. 읽음은 입력 대기 해제와 별개다. 현재 창 소유권과 세션 실행 세대를 확인해 알림을 클릭한 시점의 패널로 이동한다. 열려 있는 입력 대화상자는 유지하며 닫은 뒤 이동한다. 종료된 터미널은 자동 재실행하지 않는다.

활성 창에서 터미널을 선택해 보면 그 터미널의 미읽음 알림을 모두 읽음 처리하고 배지·전체 미읽음 수를 모든 창에 반영한다. 다른 패널·창의 알림은 유지한다. 이미 보고 있는 터미널의 새 알림도 읽음 기록으로 남긴다. 설정·알림함·대화상자를 보고 있거나 창이 비활성이면 자동으로 읽음 처리하지 않는다. 읽음 처리한 활동에 연결된 OS 알림 객체도 닫으며, 알림함 기록과 승인 대기 상태는 보존한다. 앱을 재시작하기 전 OS가 보관한 과거 알림의 회수는 포함하지 않는다.

새 로컬 탭은 **⌘N / Ctrl+N**, 새 Passport 창과 로컬 터미널은 **⌘⇧N / Ctrl+Shift+N**으로 연다. 전역 기본 셸·프로파일·프로젝트 폴더를 사용하고 기존 연결은 유지한다. 사용자 지정 키와 충돌하면 기존 설정을 보존하며 **설정 → 단축키**에서 조정한다.

연동을 끄면 이미 열린 세션의 해당 AI 알림 수신도 즉시 차단한다. 다시 켜도 이전 실행의 수신 권한을 되살리지 않으며, 새 터미널에서 시작해야 적용된다. 셸에 이미 로드된 함수와 CLI 프로세스는 계속 사용할 수 있다.

기록은 SQLite에 최대 500개·7일 보관한다. 재시작 시 과거 알림을 다시 띄우지 않으며 대기 상태는 과거 기록으로 바뀐다. 세션 토큰·도구 인자·전체 대화는 알림 DB와 내보내기에 넣지 않는다. **응답 내용 포함**을 켠 경우에만 이후 완료 알림에 마지막 응답을 최대 200자 저장한다. Mac ⌘⇧I / Windows Ctrl+Shift+I는 알림함, Mac ⌘⇧U / Windows Ctrl+Shift+U는 최근 미확인 터미널 이동이다. 설정에는 현재 OS의 키만 표시하며 각각 추가·변경·해제할 수 있다.

**운영체제 알림 설정 열기**에서 Passport의 알림 허용과 배너 표시를 켜고, **테스트 알림 보내기**로 표시 여부를 확인한다. macOS는 시스템 설정 → 알림 → Passport, Windows는 설정 → 시스템 → 알림에서 변경한다. 앱이 테스트 알림을 요청했다는 메시지는 OS 권한이나 화면 표시 성공을 보장하지 않는다. OS 권한, 방해 금지, CLI 훅 비활성화와 CLI 버전에 따라 전달되지 않을 수 있다. Windows 설치본의 알림 클릭과 실제 Claude/Codex 입력 대기는 각 대상 기기에서 확인해야 한다. [macOS 알림 설정 안내](https://support.apple.com/guide/mac-help/mh40583/mac).

## AI에서 친구에게 쪽지하기

**설정 → 쪽지**에서 네트워크·다운로드 폴더를 적용하고 **쪽지 → 등록키 복사**로 상대와 등록합니다. 양쪽 사용자가 각각 상대 별칭을 정하고 등록을 승인해야 합니다. 이 권한은 터미널 조회·입력 권한과 별개입니다.

쪽지를 켠 뒤 새 로컬 터미널에서 `passport share friends --json`을 실행하면 **쪽지 → 내 친구**와 같은 목록을 받습니다. 응답의 `value` 배열에서 `name`은 사용자가 정한 별칭, `id`는 기기 ID입니다. AI는 사용자가 지정한 상대를 이 목록에서 확인한 다음 `passport share send --to "승민" --text "문서를 확인해 주세요." --file "./문서.pdf"`처럼 전송합니다. 별칭이 겹치면 사용자가 확인한 기기 ID를 사용하고 임의로 선택하지 않습니다. 기존 `passport share peers`도 사용할 수 있습니다.

발신 응답은 전달 완료가 아닙니다. 반환된 전송 ID로 `passport share status <전송-ID> --json`을 조회하고 `delivered`에서만 완료로 안내합니다. 수신 승인은 상대가 앱에서 직접 하며 AI·CLI는 승인하거나 받은 본문을 읽을 수 없습니다. [쪽지 가이드](sharing.md#ai와-cli-사용)에 쪽지·Markdown·파일 전송과 취소 절차를 정리했습니다.

## 데이터 이행과 배포 구성

- DB 스키마 **3/4 → 5**, 문서·portable package **1 → 2**. 기존 DB는 `before-v5-<timestamp>.sqlite` 백업 후 트랜잭션으로 이행한다. 여러 탭을 묶은 이전 템플릿은 제거하며 단일 탭 템플릿·열린 작업 배치·호스트는 유지한다. 가져오기에서도 여러 탭 템플릿을 제외하고 미리보기에 개수를 표시한다. 암호화 envelope의 버전 1과 AAD는 유지하며 구버전 앱은 DB 5를 거절한다.
- 기존 Windows `default`/`powershell` 선택은 이행 시 현재 해석된 PowerShell 버전으로 고정한다. 가져온 로컬 설정은 폴더·셸·프로파일 검토 후 다시 시작해야 한다. 프로파일 ID 충돌은 가져온 참조를 새 ID로 치환해 보존한다.
- `native/helper/`: 외부 Node/Python/jq 없이 JSON을 처리하고 Unix socket/Windows named pipe로 전달하는 Rust 프로그램. stdin과 argv 어댑터 분리, 입력 256 KiB·전송 16 KiB·500 ms 제한, 세션 실행 세대와 토큰 확인, run ID로 종료 후 이벤트 차단.
- OSC 파서는 메인에서 원본 PTY 스트림에 한 번만 적용한다. 렌더러 snapshot 재생·창 이동 때 이벤트가 재발생하지 않는다. 이는 계획의 렌더러 파서안에서 변경한 구현 선택이다.
- `resources/terminal/runtime-manifest.json`: Portable Git 버전·x64 SHA-256 고정. `scripts/prepare-runtime.mjs`는 체크섬 확인 후 압축을 풀고 사용자 `.bash_profile` 자동 생성 스크립트를 비활성화한다. 원본과 수정 설명을 번들에 함께 보존한다.
- helper·런타임은 asar 밖의 대상 OS/아키텍처별 리소스로 배포한다. 패키징 전 누락 검사를 수행하며 Rust 의존성 라이선스도 수집한다. Windows AUMID는 NSIS와 메인 모두 `io.passport.desktop`을 사용한다.

## 검증 범위

Mac에서 타입 검사, Rust helper 빌드·단위 검사, 실제 PTY의 zsh 초기화·CLI fixture 실행·셸 복귀, 특수문자 경로, 알림 인증·중복·세대 폐기·보관 한도, 혼합 배치·알림 이동·프로파일 설정 GUI를 검증한다. CLI fixture는 실제 AI 서비스에 요청하지 않는다.

2026-10-01 별도 점검에서 설치된 **Claude 2.1.286의 `--print`**, **Codex 0.159.3의 `exec --ephemeral`**로 최소 응답을 실제 요청했고, 각각 응답 종료 신호·응답 완료 기록과 종료 코드 0을 확인했다. 원래 사용자 설정을 수정하지 않고 임시 앱 데이터와 작업 폴더를 사용했다. 실제 대화형 승인 화면·공유 데몬까지 검증한 결과는 아니다. 수정 설치본의 GUI에서는 직접 입력한 CLI fixture의 승인/완료 신호, 전경에서 배너 생략·배경에서 배너 요청을 확인했다.

Windows x64는 공식 번들 다운로드·SHA-256·필수 실행 파일·패치 확인과 Rust 대상 `cargo check`를 수행했다. 이후 1.1.0 Windows x64 CI에서 helper·내장 Bash 준비·기본 검사·빌드·EXE 생성·설치 범위 검사를 통과했으나 패키지 검증 단계가 실패했다. Windows EXE는 사용자 기기에서 후속 확인하기로 해 공개하지 않았으며 자동 게시 연결도 해제했다. [해당 실행과 Mac 공개 결과](verification.md)를 확인한다. 이 결과를 Windows 전체 셸·OS 알림 검증 완료로 취급하지 않는다. `.github/workflows/desktop.yml`은 Windows x64 수동 검증을 제공한다. 실제 대화형 Claude/Codex 승인·공유 데몬, 제한된 PowerShell 실행 정책, 사용자 셸 플러그인 전체와 오프라인 Windows 설치는 별도 실기 검증 항목이다.

## 터미널 복사와 중단

Windows의 기본 Ctrl+C는 선택한 텍스트를 복사하고 선택이 없으면 아무것도 하지 않는다. 중단은 Ctrl+Shift+C로 분리한다. Mac은 ⌘C 복사·Ctrl+C 중단이다. **설정 → 단축키**에서 현재 OS의 복사·붙여넣기·중단·EOF·일시 정지·CLI 이미지 입력을 모두 변경·해제할 수 있다. 예전 기본 복사 키는 새 기본값으로 이전하며 사용자 지정과 명시적 해제는 보존한다.

## 사용자 개입 알림

새 설정의 배너 기본값은 **해당 터미널을 보고 있지 않을 때**이며 기존 저장값은 유지한다. 같은 요청의 읽음과 해결 상태는 별개다. 알림을 누르거나 해당 패널을 보아도 미해결 승인·질문 표시는 유지하고, 대응하는 처리·새 턴·종료 신호에서 해제한다. CLI가 식별자와 처리 신호를 제공하지 않으면 현재 대기 상태 대신 확인 요청 기록만 표시한다.

**응답 내용 포함**은 기본 꺼짐이다. 켠 뒤 수신한 완료 알림에만 마지막 응답의 최대 200자를 저장하며, CLI 전체 대화·도구 인자는 수집하지 않는다. 배너에 내용도 표시하려면 **데스크톱 알림 설명 표시**를 함께 켠다. 꺼도 이전에 사용자가 켜서 저장한 기록은 남으며 **알림함 → 기록 지우기**로 지울 수 있다. `idle_prompt`와 진행률은 추가 알림을 만들지 않는다.

사용자 지정 CLI 설정은 덮어쓰지 않는다. Codex의 기존 notify·TUI 설정 충돌과 CLI 버전에 따라 일부 연동이 생략될 수 있으며 터미널 시작 안내와 알림 설정 안내를 확인한다. 실제 대화형 CLI와 OS 배너는 모의 이벤트·숨김 GUI 검사와 구분해서 검증한다.
