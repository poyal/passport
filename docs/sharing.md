# 사용자 간 메시지·파일 공유

공유는 기본 꺼짐입니다. 같은 LAN 또는 사설 VPN에서 등록한 Passport 기기끼리 메시지와 파일을 주고받습니다. 상대 IP만 알아서는 등록하거나 전송할 수 없습니다. IPv4 사설 주소·링크 로컬·CGNAT VPN 주소를 지원하며 인터넷 중계, 공인 IP 직접 연결, 공유기 포트 개방, IPv6 연결은 제공하지 않습니다.

## 설정과 사용자 등록

1. 양쪽 앱에서 **설정 → 공유**를 엽니다. **공유 사용**을 켜고 **사용할 네트워크**, **기본 다운로드 폴더**를 확인한 뒤 **공유 설정 적용**을 누릅니다. 처음에는 `다운로드/Passport`에 저장합니다. 켤 때는 네트워크와 저장 폴더가 모두 필요하며, 적용 중이거나 변경 사항이 없으면 버튼이 비활성화됩니다. 네트워크를 잃었어도 공유를 끄는 설정은 적용할 수 있습니다.
2. 한쪽에서 **공유함 → 등록키 복사**를 누릅니다. 키를 만들어 바로 복사하며, 설정의 **등록키 만들기 → 등록키 복사**도 사용할 수 있습니다. 직접 전달하거나 이미 사용하는 신뢰할 수 있는 메신저로 상대에게 보냅니다. 키는 생성 후 5분 동안 한 기기만 요청할 수 있습니다. 유효한 키를 다시 복사해도 만료 시간이 늘거나 진행 중인 등록 요청이 취소되지 않습니다.
3. 상대가 **상대 별칭**과 **상대에게 받은 등록키**를 입력하고 **등록 요청 보내기**를 누릅니다.
4. 등록키를 만든 쪽은 **공유함 → 사용자 등록 요청**에서 기기 지문과 등록키를 전달한 상대가 맞는지 확인합니다. 이 앱에서 사용할 **상대 별칭**을 입력한 뒤 **사용자 등록 승인**을 누릅니다. **등록 거절**도 가능합니다.
5. 양쪽 **공유함 → 내 친구**에 나타나면 사용할 수 있습니다. 별도의 내 표시 이름은 없으며, 별칭은 각 앱에서 따로 정합니다. 기기는 최대 100개이며, CLI에서 같은 이름이 여럿이면 정확한 기기 ID를 지정해야 합니다. **친구 관리**는 설정의 등록된 사용자 관리로 이동하며, **이름 수정**, **주소 수정**, **차단**, **등록 해제**를 제공합니다.

**주변 사용자 검색 및 내 기기 표시**는 선택 사항입니다. 켜면 선택한 네트워크에 일반 기기 표시와 연결 주소를 알립니다. 사용자가 정한 친구 별칭이나 이전 내 표시 이름은 알리지 않습니다. 검색 결과는 인증되지 않은 안내 목록이며, 자동 등록이나 자동 수신으로 이어지지 않습니다. 네트워크의 multicast 정책 때문에 검색되지 않더라도 등록키로 등록할 수 있습니다.

기본 공유 포트는 처음 켤 때 선택해 보관하며 재시작해도 유지합니다. IP가 바뀌면 **주소 수정**에 `IPv4:포트`를 입력합니다. 같은 주소라도 기기 인증서가 다르면 연결을 거절합니다. **차단**·**등록 해제**·공유 끄기는 진행 중인 전송과 대기 요청을 취소합니다. 네트워크 인터페이스가 사라지면 공유를 중지하므로 다시 선택·적용하세요.

기기 인증서는 1년간 유효합니다. 만료되거나 기기키를 교체할 때는 **공유 기기키 초기화**를 사용합니다. 공유와 기존 등록을 해제하고 다음 활성화 때 새 키를 만듭니다. 상대도 이전 등록을 해제하고 새 등록키로 다시 등록해야 합니다. 받은 메시지와 저장한 파일은 유지합니다.

## 보내기와 수신 승인

공유함은 **받은 메시지**, **보내기**, **내 친구** 탭으로 나뉘며 처음 열면 받은 메시지가 보입니다. **보관 메시지 불러오기**로 보관함을 열고 메시지를 선택하면 Markdown 뷰어가 표시됩니다. **내 친구**에서는 별칭·연결 주소·차단 여부를 확인합니다. 필요하면 **친구 목록 불러오기**를 누르세요. 주소 표시는 상대의 온라인 상태를 보장하지 않습니다.

**공유함 → 보내기**에서 **받는 사람**을 고르고 Markdown 메시지를 입력해 **메시지 보내기**를 누르거나 **파일 보내기**에서 파일 하나를 선택합니다. **내 친구 → 보내기**를 누르면 그 친구를 받는 사람으로 선택한 보내기 탭으로 이동합니다. 발신 후에는 상대의 수신 승인을 기다립니다. 발신자에게 별도의 승인 팝업을 반복해서 요구하지 않습니다.

수신자는 공유함에서 매번 승인해야 합니다. 승인 전에는 발신 기기·종류·파일 이름·크기·해시만 전달하고 본문을 보내지 않습니다. **메시지 받기**, **승인하고 저장**, **거절**로 처리합니다. 공유함 버튼에 승인 대기 건수를 표시하며 OS 알림을 허용한 경우 내용 없는 승인 요청 배너도 표시합니다. 요청은 10분 후 만료됩니다.

| 받은 내용 | 앱에서 가능한 동작 |
| --- | --- |
| 텍스트 | Markdown으로 표시, 전체 Markdown 복사, 코드 블록 복사, 메시지 삭제 |
| 파일 | 선택한 다운로드 폴더에 저장만 수행 |

Markdown의 HTML·스크립트·iframe은 실행하지 않습니다. 링크는 클릭할 수 없는 문자로, 이미지는 대체 문구로 표시하여 외부 서버에 접속하지 않습니다. MDX·Mermaid 실행, 원격 이미지 로드, 파일 미리보기, 터미널 자동 입력, AI에게 자동 전달, CLI로 받은 본문 읽기는 제공하지 않습니다. 사용자가 복사한 다음 외부 프로그램에서 사용하는 동작은 별개입니다. 지나치게 긴 줄·깊은 중첩·많은 줄은 문법 처리를 제한하고 뷰어에서 원문을 안전하게 표시하며 전체 복사는 유지합니다.

첨부한 `.md`·`.html`도 파일로만 저장합니다. 앱에서 열기·실행·압축 해제하지 않습니다. 허용 형식은 `pdf`, `txt`, `md`, `csv`, `docx`, `xlsx`, `pptx`, `hwpx`, `html`, `htm`, `png`, `jpg`, `jpeg`, `gif`, `webp`, `zip`, `7z`이며 파일 하나당 100 MiB, Markdown 메시지는 UTF-8 256 KiB까지입니다. 파일의 확장자·서명 검사와 OS 다운로드 보호는 악성 파일이 없다는 보증이 아닙니다. 외부 앱에서 파일을 여는 결정은 사용자가 합니다.

같은 이름의 파일이 있으면 `(1)`, `(2)`를 붙여 기존 파일을 보존합니다. 저장 경로·크기·SHA-256·OS 보호 표시를 검사한 뒤 파일을 공개합니다. macOS는 quarantine, Windows는 Attachment Execution Services의 `Save`와 Internet Zone 표시를 사용합니다. 보호 표시를 보관할 수 없는 파일시스템에서는 저장을 실패 처리합니다. 중단된 임시 파일은 즉시 정리하고, 앱이 비정상 종료했다면 다음 공유 활성화 때 소유 기록을 확인해 정리합니다.

## 보관과 암호화

기기 간 메시지·파일·전송 메타데이터·승인 응답은 **TLS 1.3**으로 암호화합니다. 등록 후에는 양쪽 인증서와 정확한 기기 지문을 확인합니다. 등록키는 상대 인증서와 256비트 일회용 비밀값을 담은 초대이며 그 문자열 자체가 암호문은 아닙니다. 등록 요청 전용 연결에서도 TLS를 사용하고, 등록키를 통한 인증과 수신자의 등록 승인까지 필요합니다. 키가 다르거나 인증서가 바뀌면 연결하지 않습니다.

개인키·등록 상대·받은 메시지는 별도 `share.sqlite`에 Electron `safeStorage`를 통해 암호화해 보관합니다. macOS Keychain·Windows DPAPI를 사용할 수 없으면 평문으로 저장하지 않고 실패합니다. 기존 설정 내보내기·자동 백업·활동 기록에는 공유 내용과 기기키를 넣지 않습니다. 다운로드 파일은 일반 파일이므로 앱의 메시지 암호화 저장 범위에 포함되지 않습니다.

**메시지 자동 정리**는 **자동 정리 안 함** 또는 **1–30일 후**, 기본 **7일 후**입니다. 이미 받은 메시지에도 적용하며 앱 실행 중과 메시지 조회 시 만료 데이터를 삭제합니다. 앱이 꺼져 있는 동안의 벽시계 예약 작업은 수행하지 않습니다. 받은 메시지의 전체 저장 한도는 1 GiB이며 화면에는 최근 100개를 표시합니다. 다운로드 파일은 자동 삭제하지 않습니다.

파일 수신 완료 후 앱은 임시 파일과 상세 전송 이력을 잊습니다. CLI 결과 확인을 위해 ID·결과 상태와 요청 인증에 필요한 최소 정보를 메모리에 최대 10분 남깁니다. 앱 재시작 시 사라집니다. 통신 오류로 완료 여부를 확인할 수 없을 때는 자동 재전송하지 않습니다. 저장된 파일이 있는지 상대에게 확인한 뒤 다시 보내세요.

## AI와 CLI 사용

공유를 켠 뒤 **새 로컬 터미널**에서 실행합니다. 기존 터미널에는 새 권한을 주입하지 않습니다. 공유 권한은 **로컬 터미널 → CLI 접근**의 조회·입력 권한과 별개입니다. 공유를 껐다가 다시 켜면 이전 CLI 권한은 되살아나지 않으므로 새 터미널이 필요합니다.

먼저 친구 목록을 확인합니다. 앱의 **내 친구**와 동일한 등록 목록이며 주변 기기를 자동 등록하거나 상대에게 알림을 보내지 않습니다.

```sh
passport share friends
passport share friends --json
```

일반 출력은 `DEVICE ID`, `ALIAS`, `BLOCKED` 열을 표시합니다. JSON 응답의 `value` 배열에는 `id`(기기 ID), `name`(이 앱에서 정한 별칭), `blocked`(차단 여부)가 있습니다. 기존 `passport share peers --json`도 같은 결과를 제공합니다.

AI는 다음 순서로 사용합니다.

1. `passport share friends --json`으로 등록 목록을 읽고 사용자가 지정한 정확한 별칭을 찾습니다.
2. 같은 별칭이 여럿이면 임의로 고르지 말고 사용자에게 대상을 확인한 뒤 `--to`에 해당 기기 ID를 넣습니다. 차단된 친구에게는 보낼 수 없습니다.
3. 사용자가 요청한 내용만 아래 명령으로 보내고 반환된 전송 ID를 보관합니다.
4. `passport share status`로 수신 결과를 확인합니다. `pending`은 상대 승인 대기이며 `delivered`일 때만 전달 완료로 안내합니다. 실패·응답 유실 때는 자동 재전송하지 않습니다.

```sh
passport share send --to "승민" --text "# 작업 결과"
passport share send --to "승민" --markdown-file "./결과.md"
passport share send --to "승민" --markdown-file - < "./결과.md"
passport share send --to "승민" --file "./문서.pdf"
passport share status <전송-ID> --json
passport share cancel <전송-ID> --json
```

`--markdown-file`은 UTF-8 본문을 메시지로 보내고, `--file`은 첨부 파일로 저장하도록 요청합니다. `send`는 준비 상태와 ID를 즉시 반환합니다. `delivered`가 되어야 수신 측 저장을 확인한 것입니다. 등록·수신 승인·설정 변경·받은 메시지 조회는 CLI 명령으로 제공하지 않습니다.

AI에게 “승민에게 이 문서를 보내 주세요”라고 요청하면 AI가 이 명령을 사용할 수 있습니다. 보내는 내용의 선택은 사용자와 AI의 책임입니다. 받은 텍스트를 AI에 자동 주입하거나 받은 명령을 터미널에서 자동 실행하지 않습니다. 기존 터미널 CLI 접근을 별도로 허용한 경우의 화면 읽기 권한과 혼동하지 마세요.

## 보안 검토 범위와 배포 조건

- 네트워크 공격자·등록되지 않은 기기·브라우저 요청: TLS 1.3, 서버 지문 고정, 등록 후 상호 인증, Origin 거부, 등록 전용 경로 분리로 제한합니다.
- 승인 우회·재전송·변조: 승인 기기/ID/크기/해시를 바인딩하고 한 번만 수신합니다. 차단·끄기·만료 시 승인도 폐기합니다. 승인 후 본문이 달라지면 저장하지 않습니다.
- 파일 경로 공격: 이름·확장자 제한, 일반 파일 검사, 선택 폴더의 실제 경로 확인, 소유 임시 폴더, 배타적 생성·hard link로 덮어쓰기와 경로 탈출을 제한합니다.
- 자원 사용: 연결 32개·IP당 4개, 수신 대기 20개, 기기별 요청 제한, 동시 발신/수신 각각 2개, 본문 크기·시간 제한을 적용합니다. 발신 요청은 TLS 연결부터 응답 본문 완료까지 메타데이터 30초·파일/메시지 본문 업로드 120초로 제한하며, 소켓의 30초 무응답 제한도 유지합니다. 조금씩 응답을 보내는 상대도 전체 제한을 연장할 수 없습니다.
- 보호 범위 밖: 초대 전달 메신저나 등록 기기의 침해, 같은 OS 사용자 권한의 악성 프로그램, 사용자가 외부에서 연 첨부의 취약점, AI가 선택해 발신한 민감 정보입니다. IP·포트·전송 시점/크기는 네트워크 관찰자가 볼 수 있습니다. 주변 검색을 켜면 Passport 기기의 존재와 연결 주소가 해당 네트워크에 공개됩니다.

소스 검사와 loopback E2E를 실제 서로 다른 PC·LAN/VPN·OS 권한 검사로 표시하지 않습니다. Windows 네이티브 AES/Zone 보호와 DPAPI, macOS 서명 앱의 Keychain/로컬 네트워크 허용·거부, 실제 두 기기의 검색·방화벽·인터페이스 변경 검증이 끝나기 전에는 양쪽 OS 보안 검토와 공개 배포가 완료된 것으로 판정하지 않습니다. 실행 결과는 [검증 기록](verification.md)에 따릅니다.

2026-10-16 Mac 1.3.0은 사용자가 남은 실기 검증을 추후 진행하고 Mac만 게시하도록 명시해 예외 배포했습니다. Windows 1.3.0은 미게시이며 위 실기 항목은 여전히 검증 대기입니다. [이번 보안 검토와 예외 범위](security-review-20261016.md).
