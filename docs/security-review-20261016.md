# 1.3.0 후보 보안 재검토 — 2026-10-16

최초 판정은 **공개 배포 보류**였다. 이후 사용자가 “그건 나중에 할테니 올려”, “1.3.0에 맥만올려 윈도우는 집가서 올릴게”라고 명시하여 Mac 1.3.0만 예외 게시했다. 남은 검증을 통과한 것으로 변경하지 않으며, 이 허용은 이번 Mac 게시에만 적용한다. [게시·검증 기록](verification.md)을 참고한다.

자동 검사와 아래 수정은 완료 범위에 기록하되, Windows 네이티브 보호·macOS 권한·실제 두 기기의 통신 검증이 끝나기 전에는 공유 기능의 보안 검토를 최종 통과한 것으로 판정하지 않는다. 기본 배포 조건은 [공유 안내](sharing.md#보안-검토-범위와-배포-조건)와 [플랫폼 개발 규칙](platform-development.md#9-공유-다운로드-보호-계약)을 따른다.

## 재현하고 수정한 문제

| 문제 | 재현과 영향 | 수정 |
| --- | --- | --- |
| 최초 기기키 생성의 동시 실행 | 같은 저장소에 동시에 8번 요청하면 서로 다른 인증서 8개를 만들었다. 연결 인증서와 저장된 키가 달라질 수 있고 초기화 중이던 작업이 기기키 재설정 뒤 완료될 수 있었다. | 생성 중인 Promise를 공유하고 재설정·종료 때 세대를 폐기한다. 공유 서비스도 설정 변경 전의 잠금 해제 결과를 거부한다. |
| 느린 상대의 응답에 전체 제한 시간 없음 | 인증된 시험 상대가 응답을 조금씩 보내면 30초 소켓 무응답 제한을 계속 피할 수 있었다. 등록 요청이나 전송 연결이 오래 유지될 수 있었다. | TLS 연결부터 응답 본문 완료까지 메타데이터 30초·본문 업로드 120초의 전체 제한을 추가했다. 기존 무응답 제한과 취소 신호도 유지한다. |

두 문제는 수정 전 회귀 시험 실패를 기록하고 수정 후 통과를 확인했다. 파일 내용 유출이나 수신 승인 우회를 재현한 것은 아니다. 추가로 요청 본문을 읽은 뒤 상대·설정 세대를 다시 검사하고, 발신 응답 뒤 취소된 작업이 대기·발신 상태로 돌아가지 않도록 검사한다.

공유 CLI E2E의 실패도 조사했다. 수신 저장은 완료됐으나, 최대 10초짜리 CLI helper 호출을 5초 `expect.poll` 안에 중첩해 이전 `pending` 응답으로 실패할 수 있었다. 승인 전 CLI의 `pending`, 실제 앱의 수신·발신 완료, 완료 후 CLI의 `delivered`를 각각 확인하도록 고쳤다. 전역 제한 시간·재시도 정책은 바꾸지 않았다.

Electron 갱신 후 Mac 패키지 E2E에서 종료 시간 초과도 관찰했다. Playwright가 비동기 `will-quit` 정리 완료 전에 디버거를 해제할 수 있어, Windows에 적용하던 최종 `quit` 확인 순서를 macOS에도 적용했다. 수정 전 단위 회귀 실패와 수정 후 배포 회귀 73개·관련 패키지 E2E 6개 통과를 확인했다. 10초 제한·정상 종료 코드·표시/포커스 감사는 유지한다.

## 의존성과 내장 런타임

- **npm 운영 의존성:** 최종 잠금 파일 감사에서 알려진 취약점 0건이다. 이 결과는 네이티브 번들 전체나 알려지지 않은 취약점이 없다는 뜻은 아니다.
- **npm 전체 의존성:** moderate 8개 항목은 빌드 전용 `sprintf-js`의 동일 공지 1종에 연결된다. 공격자가 포맷 문자열의 정밀도를 제어하면 예외·서비스 거부가 생길 수 있다. `electron-builder → app-builder-lib → @electron/get → global-agent → roarr → sprintf-js` 경로이며 검토 시점 수정판이 없다. 검토한 `global-agent` 로그는 포맷에 상수 문자열을 사용하고 URL·헤더·오류는 context 객체로 전달한다. 운영 의존성 경로는 없지만 경고 자체를 해결됐다고 표시하지 않는다. [공식 공지 GHSA-hp3w-g68c-fv3c](https://github.com/advisories/GHSA-hp3w-g68c-fv3c).
- **Rust:** `Cargo.lock`의 registry 패키지 22개 이름·버전을 OSV에 조회해 일치 공지 0건을 확인했다. `cargo audit` 실행이나 바이너리 전체 분석으로 표시하지 않는다. [OSV API](https://google.github.io/osv.dev/api/).
- **Electron:** 44.4.5에서 44.8.0으로 올렸다. Chromium 152.0.7977.167·Node.js 24.22.0과 Chromium/V8 수정이 포함된 공식 릴리즈다. [Electron 릴리즈](https://github.com/electron/electron/releases/tag/v44.8.0).
- **Windows Passport Bash:** 고정 버전을 Git for Windows 2.56.0.windows.1에서 2.56.0.windows.2로 갱신했다. OpenSSL 3.5.9와 Git 실행 파일의 누락된 Authenticode 서명 복구를 포함한다. OpenSSL은 이 버전을 최고 High 등급 수정이 포함된 보안 패치로 공지했다. 각 CVE의 Passport 경로에서의 악용 가능성을 모두 재현했다는 뜻은 아니다. 공식 PortableGit 파일 SHA-256 `075e158ef8e1f0ab80b347e245405d3eca735c2dc88fd8e032e137d0ca61f61b`를 대조하고 압축 해제·필수 실행 파일·홈 설정 생성 방지 패치를 확인했다. Mac에서 파일을 준비한 것이므로 Windows 실행·서명 신뢰 검증은 대기다. [Git for Windows 릴리즈](https://github.com/git-for-windows/git/releases/tag/v2.56.0.windows.2), [OpenSSL 보안 수정](https://openssl-library.org/news/openssl-3.5-notes/index.html).

코드 검토와 시험 범위에서 새로운 승인 우회·임의 파일 실행 경로를 확인하지 못했다. 등록된 기기·동일 OS 계정이 침해된 경우, 사용자가 외부 앱에서 첨부를 여는 경우, AI가 잘못 선택한 내용을 발신하는 경우는 별도 위험이다. 초대 전달 경로도 신뢰해야 한다. 모든 취약점 부재를 보증하는 외부 침투 시험 결과는 아니다.

## 공개 전 남은 검증

시험 전용 계정·무해한 메시지와 파일을 사용하고 실제 등록키·개인키·CLI 토큰을 보고서에 넣지 않는다.

| 항목 | 실행 환경과 통과 조건 | 현재 상태 |
| --- | --- | --- |
| Mac 암호화 저장 | 최종 앱에서 모의하지 않은 Keychain으로 저장·재시작 복구, 접근 거부 시 평문 저장 없이 실패 | 대기 |
| Mac 로컬 네트워크 | 최종 앱의 로컬 네트워크 권한 허용·거부·복구, 선택 인터페이스 유지와 오류 안내 | 대기 |
| Windows 수신 보호 | Windows 11 x64 최종 앱에서 DPAPI 재시작 복구, 실제 Attachment Execution Services 저장, 최종 파일의 Zone.Identifier 유지, 보호 실패·ADS 불가 시 파일 미공개 | 대기 |
| 실제 두 기기 | LAN·VPN의 검색·방화벽 허용/거부, 올바른/잘못된 초대·수신 거부/승인, 전송 중 연결 변경·차단·공유 끄기, 이전 CLI 권한 폐기 | 대기 |
| 정식 배포 검증 | 확정된 같은 커밋에서 각 OS의 `release:verify -- --desktop`, 소스·설치본 전체 검사와 종료 감사, 검증 파일 그대로 게시 | 데스크톱 검사 명시적 허용 필요 |

[AGENTS.md](../AGENTS.md)의 “사용자가 창 표시나 실제 데스크톱 검사를 명시적으로 요청한 경우에만 해당 모드를 사용한다”에 따라 이번 일반 검증·배포 요청에서는 숨김 검사만 수행한다. 위 항목을 자동 검사나 loopback 결과로 대체하지 않는다. 실행 결과·소스 지문·산출물은 [검증 기록](verification.md)에 기록한다.
