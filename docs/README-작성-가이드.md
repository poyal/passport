# Passport README 작성 가이드

루트 [README](../README.md)는 처음 사용하는 분이 설치부터 로컬·SSH 작업, 파일 전송, 백업과 업데이트까지 따라 할 수 있는 **사용자 매뉴얼**로 유지합니다. README를 새로 쓰거나 기능 변경·릴리즈에 맞춰 갱신할 때 먼저 이 문서를 읽고 따릅니다.

2026-10-02에 사용자가 지정한 페리로그의 `readme/README-작성-가이드.md`를 읽고 Passport의 메뉴·플랫폼·문서 경로에 맞춰 적용했습니다. Android 설치·투석·재고 관련 지침은 Passport의 데스크톱 설치·터미널·파일 전송 지침으로 바꿨습니다.

## 1. 목적과 독자

- 처음 설치한 사용자가 다음에 누를 메뉴와 버튼을 찾을 수 있어야 합니다. 기능 이름만 나열하지 말고 입력·저장·결과 확인까지 설명합니다.
- 제목은 **Passport 사용자 매뉴얼**로 유지합니다. 특정 버전을 제목이나 소개의 중심으로 삼지 않습니다.
- 한국어 존댓말과 짧고 구체적인 문장을 사용합니다. 실제 메뉴·버튼은 **굵게**, 조작 순서는 번호 목록으로 씁니다.
- 로컬 셸·SSH·AI 서비스의 차이를 설명합니다. 경로 붙여넣기를 파일 업로드나 AI 이미지 해석 완료로 표현하지 않습니다.

## 2. 기본 구성

상단에는 아이콘, 앱 소개, 지원 OS·칩, 로그인 여부, 데이터 저장 위치, 다운로드·문의 링크를 간결하게 둡니다. 처음 사용할 순서와 명시적 앵커를 사용하는 목차를 이어서 제공합니다.

다운로드는 [최신 릴리즈](https://github.com/poyal/passport/releases/latest)를 기본으로 연결하며 DMG·EXE를 고르는 방법을 설명합니다. **플랫폼별 최신 버전이 다를 때에는 실제 설치 파일이 있는 이전 플랫폼 릴리즈 링크를 함께 표시합니다.** 새 Mac 릴리즈에 없는 Windows 파일을 최신 링크에서 받을 수 있다고 안내하지 않습니다. 플랫폼 버전이 같아지면 불필요한 고정 링크를 제거합니다.

| ---- | ------------------------- | ---------------------------------------------------------- |
| 1    | 설치하기                  | OS·칩에 맞는 설치 파일 선택, 최초 실행, 서명 상태 확인     |

| 6    | 파일 전송하기             | 양쪽 연결·경로 선택, 복사·충돌 처리, 결과·재시도 확인      |

마지막에는 문의·오류 신고, 화면 안내, 상세 사용법, 변경 이력과 개발·검증 문서를 연결합니다. 새 기능만 남기거나 기존 기본 사용 절차를 삭제하지 않습니다.

## 3. 사용 절차

각 작업은 **진입 위치 → 입력·선택 → 저장·확인 버튼 → 결과** 순서로 씁니다. 버튼 이름과 동작은 현재 화면·구현을 확인하며 계획 문서만 보고 구현된 것으로 쓰지 않습니다.

다음 차이를 해당 작업 옆에 설명합니다.

- **로컬과 SSH:** 파일의 로컬 경로를 SSH에 붙여도 원격 파일이 되지 않습니다. 파일 전송에서 업로드한 뒤 원격 경로를 사용합니다.
- **파일과 이미지:** 파일 복사는 원래 전체 경로를, 이미지 픽셀은 저장한 PNG 경로를 입력합니다. 일반 파일 이름 텍스트에서 경로를 추측하지 않습니다.
- **붙여넣기와 실행:** 붙여넣기는 Enter를 추가하지 않으며 **명령 실행**은 Enter까지 전달합니다.
- **앱 단축키와 CLI 단축키:** Mac ⌘V·Windows Ctrl+V와 Mac Ctrl+V·Windows Alt+V의 전달 대상을 구분합니다. 사용자 지정 키가 우선합니다.
- **알림 읽음과 기록:** 보고 있는 활성 터미널의 미읽음만 지우며 다른 터미널·기록·승인 대기는 유지합니다.
- **템플릿과 실행 상태:** 탭 하나의 배치·설정을 저장하며 프로세스·AI 대화·실행 중 연결을 저장하지 않습니다.
- **복사와 삭제:** 충돌 처리 방식, 전송 중단·재시도, 휴지통을 거치지 않는 삭제를 설명합니다.
- **내보내기와 복구:** 인증 정보 포함 여부·별도 암호·미리보기·복원 범위를 설명합니다. 사용자 DB와 자동 로컬 백업을 기기 간 동기화로 표현하지 않습니다.
- **업데이트와 실행:** 기존 앱을 완전히 종료한 뒤 대치하고 데이터 유지와 재연결을 안내합니다. 다운로드와 자동 설치를 혼동하지 않습니다.

## 4. 화면 배치와 관리

스크린샷은 해당 조작 설명 가까이에 둡니다. 실제 앱 화면을 사용하고 촬영용 예제 데이터임을 밝힙니다. 실제 서버·사용자 DB·개인 키·비밀번호는 촬영하지 않습니다.

- 데스크톱 화면은 글자가 읽히는 너비로 배치하고 이미지에 설명하는 `alt`와 원본 링크를 넣습니다. 모바일용 260px 폭을 그대로 적용하지 않습니다.
- 사진 수를 고정하지 않으며 모든 캡처를 README에 넣을 필요도 없습니다. 기본 작업 설명을 이미지나 접힌 영역 안에만 두지 않습니다.
- PNG는 `docs/assets/`, 촬영 버전·조건·화면 목록은 [스크린샷 안내](screenshots.md)에 둡니다. `design/`의 시안을 실행 화면이나 검증 근거로 사용하지 않습니다.
- 변경되지 않은 화면은 재사용할 수 있습니다. 바뀐 화면을 최신 화면이라고 표시하지 않으며 파일 이름만으로 촬영 버전을 판단하지 않습니다.
- 촬영은 [스크린샷 안내](screenshots.md)의 격리 데이터·루프백 fixture를 사용합니다. 실행 중인 사용자 앱과 DB를 초기화하거나 교체하지 않습니다.

## 6. 수정과 확인 순서

1. 변경 기능의 화면·버튼·동작과 현재 README를 확인합니다.
2. 해당 사용 절차를 수정하고 새 절이 생기면 목차를 갱신합니다.
3. 필요한 화면과 사용 안내·스크린샷 안내·문서 목록을 맞춥니다.
4. 상대 링크·명시적 앵커·이미지 경로·표 구조와 `git diff --check`를 확인합니다. 화면을 촬영했다면 개인정보와 배치를 직접 확인합니다.
5. 수행한 확인만 기록하고 요청 범위에 따라 커밋·푸시합니다. 릴리즈에서는 검증한 소스 커밋·태그와 이후 문서 전용 커밋의 관계를 남깁니다.

완료 전에는 제목·다운로드가 불필요하게 특정 버전에 고정되지 않았는지, 처음 사용하는 분이 기본 작업을 따라 할 수 있는지, 메뉴·저장 결과·복구 제한이 실제 앱과 맞는지 확인합니다.

**문구·링크·배치만 바꿨다면 문서 확인만 수행합니다. README 때문에 앱 재빌드·전체 E2E·원격 Actions를 반복하지 않습니다.** 앱·빌드·검사 코드도 바뀌면 필요한 검사를 별도로 수행합니다. 현재 게시 도구는 정확히 검증한 소스 커밋을 요구하므로, 검증 이후 문서 마무리는 배포 후 별도 커밋으로 기록하고 태그를 이동하지 않습니다.
