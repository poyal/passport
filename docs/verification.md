## 1.0.1 GitHub 새 버전 확인 추가 — 2026-09-30

설치된 앱이 시작할 때 공개 GitHub Releases의 최신 정식 릴리즈를 한 번 확인한다. About에 수동 확인·현재/최신 버전·확인 시각·설치 파일 다운로드·변경 내역 버튼을 추가하고 새 버전이 있으면 하단 버튼으로 About에 이동한다. 앱을 자동 교체하거나 작업 중 재시작하지 않는다. Apple Developer ID 서명이 없는 현재 배포에서 사용자가 설치 파일을 받아 앱을 직접 대치하는 방식이다.

- 타입 검사·프로덕션 빌드 통과. 단위·SSH/FTP 통합 **90개 통과**, 선택 시험 2개 제외. 새 버전 숫자 비교, 사전 릴리즈·잘못된 응답 제외, OS·아키텍처·다운로드 URL 검증, 동시 요청 병합·재시도·시간 제한·응답 크기 제한·종료 시 취소를 포함한다.
- 전체 GUI **31개 통과**, 선택 10분·1GiB 부하 2개 제외. 업데이트 4개 시나리오를 추가해 다운로드 대상, 확인 중 비활성화, 최신 공개 버전보다 높은 설치본, 네트워크 오류와 미게시 설치 파일을 검사했다. 기존 SSH·탭·파일·로그·검색·설정·종료 회귀도 통과했다.
- 다크·라이트의 1440×900·1024×680 화면과 오류 화면 **5장**을 촬영하고 직접 검토했다. [로컬 업데이트 화면](../release/recheck-updates-v1.0.1/updates-dark-1440.png). 데이터는 fixture이며 1.0.2는 업데이트 안내 검사용 모의 응답이다.

## 1.0.1 내보내기·가져오기·로그·검색·설정 — 2026-09-30

내보내기 암호가 10자 미만이면 필요한 길이와 현재 글자 수를 표시한다. 실제 인증 프로필이 포함된 파일을 내보내고 올바른 암호로 복호화하는 GUI 검증을 통과했다. 가져오기는 파일 선택 후 암호화된 파일에만 암호창을 열며 잘못된 암호 재입력·미리보기·취소 토큰 무효화와 일반 파일의 암호창 생략을 확인했다. 선택한 파일의 암호문은 해당 창에서만 사용할 수 있는 5분 토큰으로 관리한다.

세션 로그 조회·검색은 UTF-8 한글·이모지를 유지하면서 CSI·OSC·DCS 등의 제어 코드를 제거한다. 제어 코드와 UTF-8 문자가 읽기 청크 경계에 걸친 경우, 색상 코드 사이에 걸친 검색어, 원본 바이트 위치의 북마크와 원본 내보내기를 검사했다. TUI 화면의 재그림은 복원하지 않으므로 반복된 텍스트가 남을 수 있다.

터미널 옵션 3개는 ON/OFF 스위치로 바꾸고 Space·Enter 전환을 확인했다. 기본·사용자 테마를 한 탭으로 합치고 작업 도구를 이름 툴팁이 있는 아이콘 버튼으로 정리했다. About에 Poyal·poyal.work@gmail.com과 설치 버전·GitHub·이슈·릴리즈·메일 링크를 넣었다. 외부 링크는 지정한 4개 대상만 열 수 있다.

터미널 검색은 결과 수·이전/다음 버튼·Enter·Shift+Enter·Esc와 테마 색상 강조를 제공한다. 첫 결과·화면 밖 결과로의 스크롤, 양방향 순환, 결과 없음, 검색 키의 서버 입력 차단, 테마 변경 시 선택 유지와 새 출력에 대한 결과 수 갱신을 통과했다. 검색창이 터미널 행 수를 바꾸지 않도록 헤더 영역을 사용한다. 강조·결과 집계는 최대 1,000개이며 한도에 도달하면 `1000+`를 표시한다.

- 타입 검사·프로덕션 빌드 통과. 단위·통합 **82개 통과**, FTP·FTPS 포함. Docker·4GiB 전송 선택 시험 2개 제외.
- GUI **고유 시나리오 27개 통과**. 전체 실행의 26개와 화면 밖 첫 강조 요소를 검사하던 테스트 대상을 수정한 검색 회귀를 포함한다. 최종 검색의 테마 변경·새 출력 검증을 추가하고 관련 GUI 6개를 다시 통과했다. 10분·1GiB 선택 부하는 이번 변경에서 재실행하지 않았다.
- 기본 12개·사용자 1개 테마의 파일 색상 검증 통과. 라이트·다크에서 1920×1080·1440×900·1024×680의 **96장**을 촬영하고 6개 개요 이미지와 주요 화면을 직접 검토했다. 가로 넘침, 카드·입력 경계와 모든 설정 탭을 검사했다. [로컬 UI 갤러리](../release/recheck-ui-v1.0.1/index.html).
- **패키징된 1.0.1 앱의 GUI 7개 통과**: 새 설정·데이터·로그·검색·About, 구형 SSH/SFTP, 모든 테마 파일 색상. 로컬 PTY 실행·렌더러 Node 접근 차단·종료 코드 0도 통과했다.
- `codesign --verify --deep --strict`와 `hdiutil verify` 통과. 패키지 내부 main·preload·renderer의 SHA-256이 최종 빌드와 일치한다. 실제 버전은 1.0.1이며 Apple 공증은 포함하지 않는다.

업데이트 확인 추가 전의 로컬 설치본: `release/Passport-1.0.1-mac-arm64.dmg`, 153,317,831바이트. SHA-256: `df6ecfe2c268f47e1366fed2d5286f9fc0354fa74c5a514fa877e2b55566eed3`. [당시 패키지 실행 기록](benchmarks/packaged-smoke-v1.0.1.json). 이 단계에서는 공개 버전이 1.0.0이었으며, 이후 업데이트 확인을 추가한 1.0.1을 위 기록대로 게시했다.

## 1.0.0 설정 재구성·자동 OS 아이콘·파일 색상 — 2026-09-30

동작 검증은 0.3.4 후보 빌드에서 수행했다. 사용자 요청으로 런타임 소스 변경 없이 배포 메타데이터를 1.0.0으로 승격한 뒤 최종 설치본을 별도로 검증했다.

외형은 앱·터미널·테마·사용자 테마, 인증은 프로필·호스트 키, 데이터 관리는 내보내기·가져오기·자동 백업, 세션 로그는 조회·보관 설정으로 나눴다. 카드의 고정 최대 폭을 제거하고 입력·목록·버튼 간격과 반응형 배치를 통일했다. 탭 전환 시 입력 초안 유지, 방향키·Home·End·연결된 tabpanel을 확인했다.

아이콘을 선택하지 않으면 호스트 이름에서 CentOS·RHEL·Rocky 등을 추정하고 접속 후 감지 결과를 우선한다. 사용자가 지정한 아이콘은 이후 OS 감지에도 유지한다. 이전 데이터의 일반 Linux 아이콘은 자동으로 이전하며 새로 사용자가 선택한 Linux는 고정된다. 사용자 원본 DB와 인증 정보를 시험에 사용하지 않았다.

창 이동 뒤 이전 창의 지연 resize·ack만 무시하고 입력·종료·명령의 소유권 검사는 유지한다. 실행 중인 SSH 분할 탭을 다른 창으로 옮기고 되돌릴 때 연결·스크롤 기록 유지와 이전 창의 입력 차단을 확인했다. 앱 종료·재실행에서는 탭·분할 배치를 복원하고 연결은 끊긴 상태로 시작하며 명시적 연결 후 정상 동작한다.

긴 파일 목록의 권한 정보를 읽어 폴더·실행 가능한 일반 파일·심볼릭 링크 **이름만** 각 테마의 blue·green·cyan으로 강조한다. 기본값은 켜짐이며 전체·호스트·세션의 외형 설정을 따른다. 색상 없는 `ll`의 한글·공백 파일명, SELinux/ACL 표기, ISO 날짜와 링크 대상을 확인했다. 대체 화면에는 적용하지 않는다. 서버의 ANSI 전경색·입출력 원문은 유지하고 확장자만으로 실행 여부를 추측하지 않는다.

- 타입 검사·최종 빌드 통과. 단위·프로토콜 통합 **80개 통과**, 선택 실행 2개 제외(Docker·4GiB 전송). FTP·FTPS fixture 포함.
- GUI **고유 시나리오 22개 통과**. 전체 실행에서 21개 통과·1개 실패는 시험의 테마 수 기대값이 임시 블랙 테마를 포함한 13개로 남아 있던 문제였다. 12개로 수정 후 해당 파일의 연결·분할·재실행·파일 UI 4개가 통과했다. 선택 10분 부하 및 새 대용량 시험은 별도 실행이다.
- 기본 **12개 + 사용자 테마 1개**에서 디렉터리·실행 파일·링크의 실제 렌더링 색을 검사하고 서버 truecolor 유지·체크박스 해제·입력 원문 유지까지 통과했다.
- 라이트·다크에서 1920×1080·1440×900·1024×680 화면 **96장**을 촬영하고 모든 설정 탭의 가로 넘침·입력/카드 경계를 검사했다. 파일 색상 13장을 추가로 촬영했다. 최소 창 라이트·다크와 넓은 창의 모든 설정, 모든 터미널 팔레트를 모은 4개 개요 이미지도 눈으로 검토했다. [로컬 갤러리](../release/recheck-ui-v0.3.4/index.html).

- 한 터미널의 16·64·256·1024MiB UTF-8 한글·ANSI·로그·주소 강조 출력과 64KiB 행 8MiB 시험 **통과(약 8.1분)**. 1GiB 단계의 처리량 **2.83MiB/s**, 앱 전체 working set 최대 **1,051MiB**, SSH 입력 왕복 **p95 1,965.2ms**, RAF 간격 **p95 33.4ms**였다. 별도 긴 행에서는 최대 1,056MiB였다. 모든 끝 표식이 실제 화면에 표시되고 연결이 유지됐다. [단계별 결과](benchmarks/terminal-large-text-v0.3.4.json).

시험은 출력 속도를 제한하지 않고 SSH backpressure를 따르는 포화 부하다. 입력 왕복에는 쌓인 SSH 출력 큐를 통과하는 대기 시간이 포함되며 일반 사용의 키 입력 지연과 같지 않다. 누적 1GiB 출력 처리까지 확인했으며 최대 지원량을 의미하지 않는다. 최근 10,000행 스크롤백과 64MiB 자동 로그 한도를 사용해 1GiB 원문 전체를 메모리에 보관하지 않는다. 이 Mac·로컬 시험 서버 외 환경의 성능을 보장하지 않는다.

최종 1.0.0 설치본에서 구형 SSH·SFTP 및 테마 파일 색상 GUI 2개(8.9초), 로컬 PTY·렌더러 Node 접근 차단·종료 코드 0 검사를 통과했다. main·preload·renderer·패치된 ssh2의 패키지 내부 SHA-256이 최종 빌드와 일치하며 앱의 실제 버전은 1.0.0이다. `codesign --verify --deep --strict` 검사 통과, Apple 공증 제외. [설치본 실행](benchmarks/packaged-smoke-v1.0.0.json), [전체 요약](benchmarks/verification-v1.0.0.json).

## 0.3.3 구형 SSH 자동 호환·옵션 제거 — 2026-09-30

사용자 요청에 따라 SHA-1 group14·GEX·group1을 모든 SSH·SFTP·터널 연결에서 현대 기본 목록 뒤에 추가한다. 호스트의 **SSH 알고리즘** 옵션과 `legacySSH` 필드를 제거했다. 이전 데이터의 `legacySSH: false`도 파싱 시 제외하므로 호스트를 다시 저장하지 않아도 자동 호환이 적용된다. 현대 방식과 구형 방식을 모두 제공하는 시험 서버에서는 `curve25519-sha256`이 선택됐다. 잘못된 비밀번호와 변경된 지문은 계속 거절한다.

## 0.3.2 구형 SSH 호환·지문 확인 설정 — 2026-09-30

사용자가 보고한 `no matching key exchange algorithm`을 SHA-1 전용 localhost 서버에서 재현했다. 호스트의 **SSH 알고리즘 → 구형 서버 호환 · CentOS 5/6**을 켜면 SHA-1 group14·GEX·group1을 기본 목록 뒤에 추가한다. 기본값과 현대 방식 우선순위는 유지하며 해당 호스트의 SSH·SFTP·터널에 함께 적용한다.

Electron 44.4.5의 BoringSSL에서는 이름 기반 `modp2`가 없어 group1을 추가해도 `Unknown DH group`이 발생했다. ssh2 1.17.0의 해당 그룹에 RFC 2409 §6.2의 동일한 소수를 명시하도록 수정했다. 설치·빌드·단위 시험에서 멱등적으로 적용하며 대상 버전이나 코드가 달라지면 중단한다. 전역 crypto API는 변경하지 않는다. 설치본의 수정된 ssh2 파일이 로컬 패치 파일과 일치함도 확인했다.

**설정 → 인증 프로필 → SSH 호스트 키 → 첫 연결 지문 확인창 표시**를 끄면 첫 지문을 자동 등록한다. 기본은 확인창 표시이며, 이미 등록된 지문이 바뀌면 설정과 관계없이 차단한다. 기본/호환 모드, 현대 방식 우선 선택, 잘못된 비밀번호, 지문 변경 차단을 시험했다.

- 타입·빌드·형식 검사 통과. 단위/프로토콜 통합 **58개 통과**, 선택 실행 2개 제외.
- 전체 GUI **20개 통과**, 선택 10분 부하 1개 제외. 마지막 버전 표시 수정 후 사용성 GUI 6개와 최종 설치본의 구형 연결 GUI 1개가 통과했다.
- 실제 Docker OpenSSH **8개 구성 통과**: 기존 6개 OS와 CentOS 7/OpenSSH 7.4의 group1·SHA-1 GEX 전용 구성 2개. 비밀번호·암호화 키·잘못된 비밀번호 거절·지문 변경 차단·sh/bash/zsh·한글·PTY·환경·1MiB SFTP 왕복 SHA-256·원격 간 전송·권한·로컬/원격/SOCKS5 터널을 확인했다. 구형 전용 구성에서 기본 모드가 연결을 거절하는 것도 확인했다. 시험 컨테이너는 모두 정리했다. [원시 결과](benchmarks/docker-ssh-v0.3.2.json).
- 최종 설치본에서 group1 SSH 터미널·한글 입력·SFTP, 첫 지문 확인창 없이 연결, 설정 저장 유지, 실제 앱 버전 표시와 정상 종료를 확인했다.
- 설치본의 로컬 PTY 실행·렌더러 Node 접근 차단·종료 코드 0 검증 통과. main·preload·renderer·패치된 ssh2의 패키지 내부 SHA-256이 최종 빌드와 일치했다. [실행 결과](benchmarks/packaged-smoke-v0.3.2.json).

사용자가 지정한 CentOS 5.11 서버에는 인증·명령 없이 협상 정보만 조회했으나 시간 초과가 발생했다. 실제 서버의 알고리즘과 로그인은 확인하지 못했다. 위 구형 구성은 CentOS 7에서 해당 알고리즘만 허용한 시험이며 실제 CentOS 5/6 OS 시험과 구분한다. 0.3.1의 10분 부하·4GiB 전송을 이번 버전의 시험 결과로 재사용하지 않는다.

## 자동 검증

- 타입·단위/통합: 기존 분할·전송·내보내기·인증 검증에 그룹 상속, 변수 치환, 단축키 충돌, 로그의 청크 경계 검색·보관 한도·북마크·내보내기, 실제 로컬 PTY, 자동 재접속 시 시작 명령 미반복, v0.1 DB 승격 검증을 추가했다.
- Electron GUI: 호스트·SSH·분할·파일·시작 시 키체인 미호출에 더해 동시 키 입력과 장치 응답 구분, 탭 변경 시 해제, 명령 실행·이력, 로그 기록, 실제 로컬 셸, 사용자 테마·단축키·출력 강조, 체크한 필드만 일괄 편집을 확인했다.
- 별도 창: 연결된 2분할을 새 창으로 옮기고 원래 창으로 복귀시켰다. SSH 연결 수가 2개로 유지되고 이전 출력과 이후 입력이 보존되며 원래 창의 잘못된 대상 입력은 거절되는 것을 확인했다.
- 새 탭 표시: 저장 응답이 창 소유 정보 이벤트보다 먼저 도착하면 새 로컬 터미널이 호스트 화면으로 되돌아가는 경쟁 상태를 수정했다. 저장 직후 문서와 소유 정보를 함께 갱신하고, GUI 시험에서 해당 이벤트를 250ms 지연시켜도 새 탭이 유지되고 명령 실행이 되는 것을 확인했다.
- 일괄 편집 화면: 항목 간 22px, 체크박스와 입력칸 사이 10px로 정리하고 미선택 필드를 비활성화했다. 실제 GUI와 스크린샷으로 확인했다.
- 스크롤: 1024×680 창에서 500개 호스트 목록의 마지막 항목과 펼친 호스트 설정의 하단 저장 버튼까지 각각 휠로 이동함을 확인했다. 선택한 호스트가 목록 밖으로 넘치지 않으며 일괄 편집 도구는 목록 위에 고정된다.
- 파일 목록: 긴 목록이 전송 대기열을 덮던 grid 최소 높이 문제를 수정했다. 100개 파일로 1024×680·1440×900 창, 대기열 접기/펼치기, 좌우 독립 휠 스크롤, 마지막 파일의 우클릭 메뉴 접근을 검증했다.
- 색상 깜박임: 출력 강조를 지웠다 다시 붙이는 처리를 바꾸고, 변경되지 않은 강조 DOM이 이후 출력에서도 유지됨을 검증했다. ANSI 지정 색상 우선과 대체 화면 강조 제외도 확인했다. xterm 6의 이전 viewport 배경이 마지막 행 아래에 검은 띠로 남던 부분도 투명 처리하여 패널 테마 배경을 표시한다.

최종 타입·단위/통합 실행은 **44개 통과, 2개 선택 실행 시험 제외**이다. GUI는 **고유 시나리오 13개를 통과**했다. 마지막 파일·테마 배경·새 탭 경쟁 상태 수정 후 관련 GUI 10개도 통과했다(10분 부하 시험 별도). 단위/통합의 제외 항목은 Docker 매트릭스와 대용량 파일 시험으로 아래에서 별도 수행한다. FTP/FTPS 시험은 Python 환경을 지정해 포함했다.

### Electron 종료 충돌 수정

사용자 보고서의 `ARM-64 (Native)`, `pty.node → ThreadSafeFunction::CallJS → Environment::CleanupHandles`로부터, 로컬 셸의 종료 콜백이 Electron의 Node 환경 해제와 겹친 것으로 판단했다. 동일 경로의 [node-pty 상위 이슈 #904](https://github.com/microsoft/node-pty/issues/904)도 참고했다. 단순 창 닫기 성공만 보던 이전 GUI 검증으로는 SIGABRT를 잡지 못했다.

로컬 셸을 종료 요청한 뒤 실제 종료 콜백 반환까지 기다리고, 이미 닫힌 탭의 콜백도 추적하도록 수정했다. 다시 연결한 패널에 이전 셸의 종료 상태가 전달되지 않도록 했다. Electron 종료 전에 정리가 끝나도록 순서를 바꾸고 모든 GUI/패키지 시험에 프로세스 종료 코드 검사를 추가했다.

4개 PTY의 활성/닫힘/재연결 상태를 각각 3회, **총 9회 반복 실행하여 종료 코드 0, 시그널 없음**을 확인했다. 별도 통합 시험에서는 종료 신호를 무시하는 셸의 강제 종료 대기와 재연결 콜백 구분도 통과했다. 전체 GUI 재실행도 정상 종료했고 신규 macOS 충돌 보고서는 생성되지 않았다.

반복 종료·단위/통합·GUI·패키지 결과의 요약은 [0.3 검증 결과](benchmarks/verification-v0.3.json)에 저장했다.

## 파일 전송 부하

현재 0.3 코드로 4GiB 파일 전송 및 SHA-256 일치, 작은 파일 10,000개 폴더 복사·일부 내용 확인을 통과했다. 시험 시간은 15.11초이며, 대용량 전송 구간의 프로세스 RSS 증가가 512MiB 미만이라는 검증을 통과했다. 두 로컬 파일 어댑터 사이의 스트리밍 시험이므로 WAN SFTP 전송 속도를 의미하지 않는다.

## 터미널 연속 출력

로그·주소 강조를 켠 16분할, 호스트 500개 프로필로 **600.002초** 실행했다. 세션별 100KiB/s 목표로 총 60,835,840바이트씩 전송했으며 평균은 약 99.0KiB/s다. 로컬 IPC/SSH 입력 왕복 지연 **p95 15ms**로 목표 100ms 이내를 통과했다. 전체 앱 프로세스의 working set은 최대 **1,147MiB**, 마지막 표본은 **1,131MiB**였다. 주기적으로 16개 터미널이 활성 화면에 남아 있는지 검사했고 마지막 앱 종료 코드도 0이었다. [원시 결과](benchmarks/terminal-stress.json).

이 수치는 같은 기기의 시험 SSH 서버를 거친 왕복 응답 시간이며 물리 키 입력부터 화면 표시까지의 지연이나 WAN 지연을 별도로 측정한 값은 아니다. 호스트·파일 GUI 검증을 병행한 구간이 포함된다. 출력 강조를 수정하기 전 중단한 실행은 완료 결과에 포함하지 않았다. 이후 마지막 행 아래 배경만 바꾸는 CSS 수정은 별도 GUI 회귀로 확인했다.

## Docker 실제 OpenSSH 매트릭스

모든 시험 컨테이너는 `linux/arm64`, 호스트 포트는 `127.0.0.1`의 임시 포트다. 암호·Ed25519 개인 키는 시험 실행 시 생성한다. 기본 SSH 암호 협상 정책을 완화하지 않았다.

| 서버                           | 결과 |
| ------------------------------ | ---- |
| Alpine 3.22                    | 통과 |
| Ubuntu 24.04                   | 통과 |
| Debian 12                      | 통과 |
| Rocky Linux 9                  | 통과 |
| CentOS Stream 9                | 통과 |
| CentOS 7 AltArch / OpenSSH 7.4 | 통과 |

각 OS에서 비밀번호·암호화 Ed25519 키, 잘못된 비밀번호 거절, 변경된 호스트 지문 거절, sh/bash/zsh 한글 출력, PTY 91×37 변경, 환경 변수, 1MiB 한글 파일의 로컬→SFTP→독립 SFTP→로컬 왕복 SHA-256, chmod 0640을 확인했다. 터널은 로컬·원격·SOCKS5 IPv4/도메인 및 분할된 핸드셰이크를 시험했고 미지원 UDP 요청 거절도 확인했다. [원시 결과](benchmarks/docker-ssh.json).

CentOS 7은 공식 ARM64 아카이브와 이미지 내 ARM64 GPG 키를 사용했다. CentOS 5/6과 모든 구형 SSH 알고리즘까지 지원한다고 의미하지 않는다. 시험 완료 후 해당 실행의 컨테이너만 제거했고 `be-withvtm-postgres`는 실행 상태로 남겨 두었다. 시험 이미지 캐시는 재실행을 위해 보관했다.

## 플랫폼·패키지

Mac은 Apple Silicon 네이티브이며 Rosetta가 필요 없다. Windows x64/ARM64는 별도 NSIS 스크립트와 네이티브 CI 구성을 제공한다. 이 작업 환경에는 Windows가 없어 실제 Windows 설치·실행 결과는 아직 없다. macOS 최소 버전 목표는 14지만 현재 실측 OS는 27이다. 개인 테스트용 Mac 패키지는 ad-hoc 서명이며 Developer ID 서명·공증은 포함하지 않는다.

생성한 설치본은 `release/Passport-0.3.0-mac-arm64.dmg`이다. 앱 실행 파일의 Mach-O arm64와 `codesign --verify --deep --strict` 통과를 확인했다. 패키징된 앱에서 로컬 PTY 명령 실행, Node 접근 차단, 정상 종료 코드 0까지 확인했다. [패키지 실행 결과](benchmarks/packaged-smoke.json).

DMG SHA-256: `32d3a54712328930a91beeab29d635f235619dd536cf9a2018fa40db34a91d46`.

Windows ARM64는 [GitHub 공식 runner 목록](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)의 `windows-11-arm`을 사용한다. [워크플로](../.github/workflows/desktop.yml)는 수동 실행이며, 이 작업에서 원격 CI·공개 업로드는 실행하지 않았다.

## 실환경 확인 범위

Windows x64/ARM64 설치·실행, macOS 14, 두 OS의 실제 한글 IME·배율·네이티브 파일 대화상자·Keychain/DPAPI 보호 흐름은 별도 환경 확인이 남는다. 한글 출력과 키/비밀번호 프로토콜 테스트는 이 OS UI 확인을 대신하지 않는다. 실제 WAN 단절·권한 제한 서버·장시간 원격 대용량 전송도 로컬 시험과 구분한다.
