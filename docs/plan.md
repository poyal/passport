# Passport 제품 계획과 구현 현황

- 상태: v0.2 후속 기능 및 v0.3 Windows ARM64 빌드 구성 구현 · Mac 로컬 검증 완료 · Windows 실환경 검증 대기
- 최초 작성 및 결정일: 2026-09-29
- 필수 플랫폼: Windows x64와 macOS Apple Silicon(arm64) 데스크톱
- 결정 근거: 사용자 요청, 제외한 기능 목록, “이거 니가 한번결정해봐”라는 결정 위임
- 현재 작업 범위: 사용자의 “후속계획 까지 완료해” 요청에 따라 v0.1~v0.3 기능 구현, Docker 여러 OS의 SSH 시험, 개인 테스트용 설치본 생성. 공개 배포는 포함하지 않음

## 결정 권한과 문서 사용

사용자가 직접 요청한 기능과 제외한 10개 기능을 유지하면서, D01~D45의 미정 항목을 에이전트가 결정했다.
이후 사용자가 정한 업데이트 제외·한국어 고정·파일 내보내기 방식이 기존 위임 결정에 우선한다.
“앱 디자인도 정해봐”라는 요청에 따라 아래 앱 디자인 결정안을 추가했다. 디자인 선택은 위임받았으며, 구현 승인을 뜻하지 않는다.
사용자가 계획을 확정하고 “Implement the plan.”으로 구현을 승인했다. 이후 “후속계획 까지 완료해”로 v0.2·v0.3까지 구현 범위를 확장했다. 아래 버전 배정은 최초 출시 순서이며, 현재 구현 상태는 이 문서의 후속 구현 현황과 검증 기록을 따른다.
아래 내용은 현재의 단일 계획 기준이다. 이전 초안의 “미정”이나 “추가 확인” 문구는 이 결정안으로 대체한다.
후속 버전으로 배정한 기능도 로드맵에 포함한 기능이며, 제외 목록과 구분한다.

## 제품 목표와 사용 가정

Termius의 호스트 관리, 좌우 파일 탐색, SSH 탭과 드래그 분할, 테마·폰트, 스니펫 흐름을 참고한 개인용 서버 관리 앱을 만든다.
사용 목적은 여러 개발·빌드·운영 서버에 접속해 명령을 입력하고 로그를 보며 파일을 전송하는 작업으로 잡는다.
이 사용 가정은 제공한 이미지에서 추론한 것으로, 사용자가 직접 확정한 업무 설명은 아니다.

- Windows와 macOS에서 같은 핵심 기능을 제공한다.
- 앱 화면 언어는 OS 언어와 관계없이 한국어로 고정한다.
- 로그인 없이 실행하며, 호스트·스니펫·설정은 로컬에 저장한다.
- 기존 요청대로 SSH·SFTP와 일반 FTP를 지원한다. 명시적 FTPS도 함께 지원한다.
- 첫 버전은 실제로 서버에 접속하고 파일을 옮길 수 있는 개인용 버전으로 완성한다.
- 개인 기기 간 설정 이동은 v0.1의 파일 내보내기·가져오기로 제공한다. 운영 편의 기능은 단계적으로 추가한다.
- 앱 업데이트 기능은 제공하지 않는다.
- 아래에 명시한 성능과 호환성은 검증할 목표이며, 이미 구현하거나 달성한 결과가 아니다.

동적 포트 포워딩은 SSH 연결로 터널을 제공하는 기능이며, 제외한 프록시 경유 접속과 별개다.

## 앱 디자인 결정안

### 방향과 검토용 시안

**차콜 계열 작업 화면에 민트 강조색을 사용하는 데스크톱 도구**로 정한다.
터미널 출력과 호스트 이름을 주된 정보로 두고, 선택한 탭·입력 대상·전송 방향을 빠르게 구분하게 한다.
제공된 Termius 화면의 탭·분할·양쪽 파일 탐색 흐름을 참고하되, Passport의 색상·간격·컴포넌트 규칙을 적용한다.
기본 화면은 호스트 목록이다. 저장한 작업 배치가 있다면 마지막 작업 탭의 배치만 복원하며 연결은 D19를 따른다.

### 창과 공통 탐색

- 최초 창 크기는 가용 화면 안에서 1440×900 CSS px를 목표로 하고, 최소 창 크기는 1024×680 CSS px로 둔다. 재실행 시 마지막 유효 크기를 복원한다.
- 상단 44px 영역에 OS 창 제어, ‘호스트’·‘파일 전송’ 고정 탭, SSH 작업 탭, 새 탭 버튼, 설정 진입을 둔다.
- macOS 창 제어는 왼쪽, Windows 창 제어는 오른쪽의 OS 규칙을 유지한다. 드래그 영역과 탭·버튼의 클릭 영역을 겹치지 않게 한다.
- SSH 탭은 140~220px, 긴 이름은 말줄임한다. 탭이 많으면 가로 스크롤과 열린 작업 탭 목록 메뉴를 제공한다.
- 선택 탭은 배경 밝기와 하단 민트 2px 선으로 표시한다. 분할 탭에는 ‘3개 세션’처럼 연결된 터미널 수를 표시한다.
- ‘호스트’·‘파일 전송’ 고정 탭은 닫기 버튼을 두지 않는다. SSH 탭에는 이름·세션 수·닫기 조작을 제공한다.
- 하단 24px 상태줄에는 현재 연결 수, 전송 수와 선택 항목의 간단한 상태를 표시한다. 상세 전송은 파일 전송 화면으로 연다.
- 설정은 작업 영역을 일시적으로 사용하는 별도 화면으로 열고 ‘작업으로 돌아가기’를 제공한다. 작업 탭과 연결은 유지한다.

### 호스트 관리 화면

**왼쪽 분류 208px / 중앙 호스트 목록 / 오른쪽 상세 320px**의 3영역으로 구성한다.

- 왼쪽은 ‘전체 호스트 / 즐겨찾기 / 최근 접속’, 중첩 그룹, 태그 순서다. 그룹·태그마다 항목 수를 표시한다.
- 중앙 상단은 검색·필터·정렬과 ‘호스트 추가’. 한 행에는 아이콘, 호스트 이름, 주소·계정, 태그, 즐겨찾기를 배치한다.
- 선택 행은 민트 계열 배경과 왼쪽 표시선으로 강조한다. 한 번 클릭하면 상세, 더블클릭하면 SSH 연결이라는 D13을 유지한다.
- 상세는 ‘기본 정보 / 연결 / 인증 / 표시 설정’ 순서다. ‘SSH 연결’, ‘파일 전송 ▾’, ‘편집’을 제공하고 파일 전송 메뉴에서 왼쪽·오른쪽을 선택한다.
- 추가·편집은 같은 상세 패널을 폼으로 전환하고 하단 ‘취소 / 저장’을 고정한다. 필수값 오류는 해당 필드 아래에 표시한다.
- 인증 값은 기본적으로 가려서 표시한다. 비어 있는 목록에는 ‘첫 호스트 추가 / 파일에서 가져오기’를 제공한다.

### 터미널 작업 화면

**터미널 영역을 최대한 사용하고 오른쪽 도구 패널은 필요할 때 여는 구조**로 정한다.

- 각 터미널은 36px 헤더에 호스트 별칭·계정·연결 상태와 분할·확대·닫기를 표시한다. 전체 주소는 호버 또는 상세에서 확인한다.
- 입력 대상 패널에는 민트 2px 테두리와 ‘입력 대상’ 표시를 둔다. 다른 패널은 중립색 1px 경계로 구분한다.
- 터미널 사이 간격은 6px. 구분선 위에 포인터를 올리면 크기 조절 커서와 민트 표시를 제공하고 실제 잡는 영역은 최소 8px로 둔다.
- 탭 드래그 중 상하좌우 드롭 영역을 반투명 민트로 표시한다. 놓을 영역에는 ‘오른쪽으로 분할’ 같은 결과 문구를 제공한다.
- 오른쪽 320px 도구 패널은 ‘스니펫 / 꾸미기’ 탭으로 구성한다. 열고 닫아도 마지막 터미널 입력 대상을 유지한다.
- 스니펫 패널 상단에 ‘선택한 창 / 현재 탭 전체’와 대상 수를 고정한다. 목록은 이름·명령 미리보기, 선택 후 하단에 대상 호스트와 ‘붙여넣기’를 표시한다.
- v0.1에는 붙여넣기만 표시한다. 실행·동시 키보드 입력 등 후속 기능은 해당 버전 도입 때 표시한다.
- 꾸미기 패널은 적용 범위 → 테마 검색·다크/라이트 필터·미리보기 격자 → 글꼴 → 크기 순서다. v0.2에 테마와 별도의 ‘출력 강조’ 선택을 추가한다. 실제 선택 범위와 변경 결과를 같은 패널에서 확인한다.
- 테마 미리보기는 배경·본문·ANSI 색상을 함께 보여 주며 선택 표시는 색상과 체크 아이콘을 사용한다.

#### 터미널 가독성과 강조 표시

사용자의 정정에 따라 특정 스크린샷의 검은 배경·주황 커서 조합을 제품 전체 기준으로 삼지 않는다.
**색상 테마와 출력 강조 방식을 각각 선택하고 조합하는 구조**로 정한다.
기존 전체 화면 시안은 Catppuccin Mocha 사용 예시다. 다른 테마에서도 앱의 탭·분할·도구 패널 구성은 유지한다.

- 커서 색은 각 테마에 맞춘다. 모든 테마에 주황색을 강제하지 않는다. 비활성 창은 윤곽선 커서, 입력 대상 패널은 앱의 민트 테두리로 표시한다.
- 미리보기는 동일한 명령·파일 목록·로그·한글 샘플로 비교하고 선택·검색 결과도 보여 준다. 테마 선택은 D32의 전체·호스트·현재 세션 범위를 따른다.

##### 출력 강조 프리셋: v0.2

‘그랩콘솔’은 확인 전까지 Grep Console을 가리키는 것으로 해석한다.
Grep Console은 일치하는 텍스트 또는 행에 색상을 적용하는 기능을 제공한다. 이 방식에서 로그 강조 표현을 참고한다. [Grep Console 공식 저장소](https://github.com/krasa/GrepConsole)
Passport는 이 플러그인을 SSH 터미널에 설치하는 방식이 아니라 자체 출력 표시 기능으로 구성한다.

| ID  | 화면에 표시할 이름 | 동작                                                                                                                           |
| --- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| H01 | 기본 출력          | 앱의 추가 강조 없이 서버가 보내는 색상과 선택한 테마를 사용. 기본값이며 v0.1 동작과 같음                                       |
| H02 | 로그 표식 강조     | TRACE·DEBUG는 보조색, INFO는 테마의 정보색, WARN은 노랑 계열, ERROR·FATAL은 빨강 계열로 로그 수준 토큰을 강조                  |
| H03 | 로그 행 강조       | Grep Console의 행 색상 방식을 참고. H02의 표식과 함께 WARN·ERROR·FATAL 행에 옅은 배경을 적용하고 본문을 읽을 수 있는 대비 유지 |
| H04 | 주소 강조          | 유효한 IPv4·IPv6 주소와 HTTP(S) URL에 테마별 강조색 적용. 포트는 주소·URL과 함께 나오는 경우에만 포함                          |

- 테마와 프리셋은 독립적이다. 예: ‘One Dark + 로그 행 강조’, ‘Nord + 주소 강조’, ‘Solarized Light + 기본 출력’.
- 프리셋을 선택한 뒤 IP·URL 강조와 로그 강조 범위를 개별 조정할 수 있다. 로그 표식·로그 행은 같은 규칙의 표시 범위를 바꾸는 선택이며 중복 처리하지 않는다.
- 기본 규칙은 로그 수준의 독립된 토큰·접두부를 기준으로 하고 파일명이나 임의 단어 일부를 무조건 오류로 판단하지 않는다.
- 로그 행의 배경은 서버가 배경색을 지정하지 않은 셀에만 적용한다. 기존 ANSI 전경색·배경색과 선택·검색·커서 표시를 우선한다.
- 시안에서 보이는 로그 행 강조는 v0.2 계획 예시다. v0.1의 ANSI 컬러 출력과 구분해 안내한다.

- `ls`의 파일 종류·확장자별 색상은 원격 명령의 컬러 출력 설정에 영향을 받는다. 모든 서버에서 테마 선택만으로 같은 파일 색상을 보장하지 않는다. [GNU ls 색상 출력](https://www.gnu.org/s/coreutils/manual/html_node/General-output-formatting.html), [dircolors 설정](https://www.gnu.org/s/coreutils/manual/html_node/dircolors-invocation.html)
- 앱은 서버가 보낸 ANSI 16색·256색·트루컬러 출력을 표시한다. 테마는 기본색과 팔레트를 정의하며 원격 프로그램이 직접 지정한 RGB 색은 유지한다. 배경·전경·ANSI·커서·선택색 설정은 xterm.js의 테마 구성을 사용한다. [xterm.js 테마 API](https://xtermjs.org/docs/api/terminal/interfaces/itheme/)
- 연결 시 `.bashrc`, `LS_COLORS`, 명령 별칭 또는 원격 프롬프트를 자동 변경하지 않는다. 클라이언트의 강조 표시 때문에 서버에 명령을 실행하지 않는다.
- v0.2의 ‘출력 강조’ 기본값은 H01 기본 출력이다. 적용 범위는 D32의 전체·호스트·현재 세션을 따른다.
- 추가 강조는 현재 표시 중인 터미널 버퍼의 텍스트에만 적용하며 원격 바이트·터미널 내용·명령 입력·복사 결과·로그 내용을 바꾸지 않는다. URL 강조만으로 브라우저를 열거나 서버에 접속하지 않는다.
- 서버가 명시한 색상을 우선한다. 앱의 추가 강조는 기본색 출력에 적용하고, 선택·검색·커서가 겹치면 해당 조작 표시를 우선한다. 앱의 토큰 강조만으로 글자 폭이나 굵기를 바꾸지 않는다.
- vim·htop처럼 대체 화면 버퍼를 사용하는 전체 화면 프로그램에서는 추가 패턴 강조를 적용하지 않는다. 사용자 정규식 편집은 이번 범위에 넣지 않는다.
- 긴 파일명은 실제 터미널 열 수에 따라 줄바꿈하며 임의로 줄이거나 말줄임하지 않는다. 창·분할·글꼴 크기 변경 시 행·열 수를 다시 계산해 원격 PTY에 전달한다.
- 한글·영문·숫자·박스 문자·넓은 문자가 섞여도 커서 위치와 선택·복사 범위를 유지한다. 화면 출력 포맷을 JSON 정렬이나 표 재구성으로 바꾸지 않는다.
- 꾸미기 미리보기에는 한글·영문 프롬프트, 컬러 파일 목록, 로그, 긴 파일명, 선택 영역·커서를 함께 보여 준다. 미리보기는 가상 데이터로 표시한다.
- 추가 강조가 켜진 상태에서도 출력 성능 목표를 검증하고, 모든 스크롤백을 입력마다 다시 분석하지 않는다.

### 파일 전송 화면

**독립된 좌우 탐색기 50:50 + 하단 전송 대기열**로 정한다.

- 각 패널 상단은 ‘로컬 또는 호스트 선택 / 프로토콜 / 연결 상태’, 다음 줄은 경로·상위 폴더·새로고침·검색이다.
- 목록은 ‘이름 / 수정일 / 크기 / 종류’ 순서다. 이름에 가장 넓은 공간을 주고 SFTP 권한은 보조 정보 또는 상세에서 표시한다.
- 서버 이름을 바꾸는 조작은 해당 패널에만 적용한다. 왼쪽·오른쪽 이름과 현재 경로를 각각 유지한다.
- 선택 파일을 반대편으로 옮기는 버튼에는 ‘오른쪽으로 복사 →’ 또는 ‘← 왼쪽으로 복사’를 표시한다. 드래그 중에는 대상 패널과 도착 경로를 강조한다.
- 하단 대기열은 기본 176px, 접으면 32px다. 파일명·출발지→도착지·진행률·속도·상태·취소 또는 재시도를 표시한다.
- 덮어쓰기 충돌은 대상 파일·선택 항목 수와 함께 ‘건너뛰기 / 이름 변경 / 덮어쓰기’를 제공하며 D25의 기본값을 유지한다.

#### SFTP 컨텍스트 메뉴

파일 목록에서 우클릭으로 자주 쓰는 작업을 연다. 메뉴는 v0.1에 포함하고 기존 복사 버튼·드래그 전송과 같은 작업을 실행한다.
우클릭 메뉴의 첫 항목에는 반대편 패널을 목적지로 하는 복사를 둔다.

| 메뉴                                      | 동작과 활성화 조건                                                                                                                            |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 오른쪽 폴더로 복사 → / ← 왼쪽 폴더로 복사 | 파일·폴더를 1개 이상 선택하고 양쪽 경로에 접근 가능한 상태에서 활성화. 반대편 호스트·현재 경로를 보조 정보로 표시하고 기존 전송 대기열에 추가 |
| 이름 변경                                 | 1개만 선택한 경우 활성화. 여러 개 선택 시 비활성화하고 ‘한 항목을 선택하세요’ 안내                                                            |
| 권한 변경                                 | 권한 정보를 읽을 수 있는 SFTP의 일반 파일 또는 폴더 1개를 선택한 경우 활성화. 링크·다중 선택에서는 비활성화                                   |
| 새로고침                                  | 연결된 현재 패널의 현재 경로를 다시 조회. 파일 선택 없이 사용 가능                                                                            |
| 새 폴더                                   | 연결된 현재 패널의 현재 경로에 생성. 파일 선택 없이 사용 가능하며 선택한 하위 폴더 안에 자동 생성하지 않음                                    |
| 삭제                                      | 1개 이상 선택 시 활성화. 메뉴 맨 아래에 구분선을 두고 빨간 글자·삭제 아이콘으로 표시. 실행 전 호스트·경로·항목 수와 휴지통 없이 삭제됨을 확인 |

- 여러 파일을 선택한 상태에서 선택된 행을 우클릭하면 선택 전체를 유지한다. 선택되지 않은 행을 우클릭하면 해당 행 하나를 새 대상으로 선택한다.
- 빈 공간을 우클릭하면 해당 패널의 파일 선택을 해제하고 ‘새로고침 / 새 폴더’만 제공한다. 반대편 패널의 선택은 유지한다.
- ‘..’ 상위 폴더 항목은 파일 작업 대상으로 취급하지 않는다. 연결이 끊긴 패널에서는 재연결 안내를 표시하고 원격 파일 작업을 비활성화한다.
- 메뉴를 열었을 때의 출발 패널·선택 항목을 대상으로 사용한다. 어느 한쪽 호스트·경로가 바뀌면 메뉴를 닫아 이전 대상에 대한 조작을 방지한다.
- 삭제·복사·이름 변경·폴더 생성은 기존 오류·충돌 처리 규칙을 사용한다. 권한 부족 여부를 목록만으로 확정하지 않고 서버가 거절하면 해당 작업의 실패로 표시한다.
- 권한 변경 대화상자는 현재 값, 소유자·그룹·기타의 읽기·쓰기·실행 체크박스와 3자리 8진수 입력을 제공한다. 예: `644`, `755`. 특수 비트는 기존 값을 유지하며 이 화면에서 변경하지 않는다.
- 권한 변경은 선택한 항목 자체에만 적용한다. 하위 폴더 재귀 적용·소유자 변경·ACL 편집은 이번 범위에 넣지 않는다. 여러 파일을 선택한 경우 일괄 권한 변경 대신 단일 선택을 안내한다.
- 권한 변경은 파일 메타데이터 조작이며, 제외된 원격 파일 내용 편집 기능을 추가하지 않는다. FTP/FTPS·로컬 목록은 공통 메뉴를 재사용하되 SFTP 권한 변경 항목은 제공하지 않는다.
- 메뉴는 기존 외형의 떠 있는 표면 색상, 폭 260~320px, 행 높이 36px, 모서리 8px를 사용한다. 화면 가장자리에서는 열리는 방향을 바꿔 메뉴가 잘리지 않게 한다.
- 비활성 항목에는 선택 수·연결·지원 여부에 따른 이유를 표시하고 실행을 차단한다. 삭제 아이콘과 문구를 함께 사용해 색상만으로 의미를 전달하지 않는다.
- Windows 우클릭·메뉴 키, macOS 보조 클릭·Control+클릭, 두 OS의 Shift+F10으로 열 수 있게 한다. 방향키·Enter·Esc를 지원하고 닫으면 원래 목록의 행 또는 컨테이너로 포커스를 돌린다.
- 키보드 사용과 메뉴 발견을 위해 각 파일 패널의 ‘작업 ⋯’ 버튼에서도 같은 메뉴를 제공한다. 이 메뉴는 파일 목록에만 적용하며 터미널의 우클릭 동작은 변경하지 않는다.

### 설정과 데이터 이동

- 왼쪽에 ‘외형 / 터미널 / 인증 정보 / 단축키 / 데이터 관리’ 분류, 오른쪽에 설정 내용을 둔다. 언어·업데이트·클라우드 동기화 항목은 두지 않는다.
- 외형의 앱 밝기와 터미널 테마를 구분해 표시한다. 호스트별 설정은 ‘전체 기본값 사용’ 여부를 함께 보여 준다.
- 데이터 관리에는 ‘파일 내보내기 / 파일 가져오기 / 로컬 백업’을 구분한다.
- 내보내기는 대상 항목 → 비밀값 포함 여부 → 저장 위치 순서다. 가져오기는 파일 선택 → 항목·중복 미리보기 → 적용 순서다.
- 성공 결과에는 이동한 호스트·스니펫 수를 표시하고, 다시 지정해야 할 경로·폰트는 항목별 안내를 남긴다.

### 작은 창·키보드·상태 표현

- 폭이 1200px 미만이면 호스트 화면의 그룹 영역을 버튼으로 접고 상세 패널 320px와 목록을 유지한다. 두 파일 패널은 좌우 배치를 유지하고 ‘종류’, ‘수정일’ 순으로 보조 열을 접는다.
- 터미널 도구 패널 때문에 최소 터미널 크기를 확보할 수 없으면 도구 패널을 임시 오버레이로 연다. 열릴 때마다 같은 패널의 별도 창을 생성하지 않는다.
- 창 축소로 분할 패널 최소 크기 320×180px를 유지할 수 없으면 작업 영역 안에서 스크롤한다. 세션 종료나 분할 구조 변경으로 해결하지 않는다.
- 모든 아이콘 버튼에는 한국어 이름·툴팁을 둔다. 키보드 포커스는 강조색 2px 외곽선으로 표시한다.
- 드래그 분할·패널 이동은 메뉴와 키보드로도 수행할 수 있게 한다. 대화상자 종료 후 이전 컨트롤 또는 터미널로 포커스를 돌린다.
- 기본 텍스트 대비 4.5:1, 주요 컨트롤·포커스 표시 대비 3:1을 디자인 검증 목표로 잡는다. 실제 적용 상태에서 검증하며 달성 결과로 간주하지 않는다.
- 로딩은 해당 영역에만 표시하고 나머지 연결은 계속 사용할 수 있게 한다. 오류는 대상 이름·원인·‘다시 시도’를 해당 패널에 남긴다.
- 목록이 비었을 때, 검색 결과 없음, 연결 전, 연결 중, 끊김, 실패, 전송 중, 완료 상태를 각각 설계한다.
- 삭제·연결 종료 확인에는 대상과 개수를 명시한다. 토스트는 복사·저장 등 짧은 완료 알림에 사용하고, 지속 오류를 토스트만으로 처리하지 않는다.
- 상태 전환은 120~160ms 이내, 드래그·크기 조절은 즉시 반영한다. OS의 동작 줄이기를 따르며 터미널 출력에 애니메이션을 추가하지 않는다.

## 핵심 화면과 동작 기준

| 화면          | 구성                                                                       |
| ------------- | -------------------------------------------------------------------------- |
| 상단 탭       | 호스트 관리, 파일 전송, SSH 작업 탭, 새 탭 버튼                            |
| 호스트        | 그룹·태그·검색, 호스트 목록, 오른쪽 상세 편집                              |
| 터미널 중앙   | 단일 SSH 또는 상하·좌우 중첩 분할, 활성 입력 대상 표시                     |
| 터미널 오른쪽 | 테마·폰트와 스니펫 패널, 스니펫 내용·대상 표시                             |
| 파일 전송     | 각자 호스트·프로토콜·경로를 선택하는 좌우 패널, 하단 전송 대기열           |
| 설정          | 테마·폰트·인증 프로필·단축키·파일 내보내기·가져오기·로컬 백업, 한국어 고정 |

### 드래그로 작업 화면 구성

1. 서버 A와 B를 각각 SSH 탭으로 연다.
2. B 탭을 A 탭 위에 잠시 올리면 A 작업 화면이 나타난다.
3. A 터미널의 상하·좌우에 드롭 위치를 미리 표시한다.
4. B를 오른쪽에 놓으면 한 작업 탭의 왼쪽 A·오른쪽 B가 된다.
5. C 탭을 왼쪽 아래에 놓으면 왼쪽 위 A·왼쪽 아래 C·오른쪽 B가 된다.
6. 경계선을 드래그해 크기를 조절하고, 한 패널을 확대하거나 다시 탭으로 꺼낼 수 있다.

취소하거나 유효하지 않은 위치에 놓으면 기존 배치를 유지한다.
단일 세션을 옮겨 비게 된 탭은 정리하고, 원래 실행 중인 SSH 연결과 터미널 버퍼는 유지한다.
분할 탭 전체 이동은 내부 분할 구조를 유지하며 목적지의 한 영역으로 삽입한다.
기존 세션을 닫는 동작과 단순 화면 이동을 별도로 처리한다.

### 스니펫 전달 대상

- ‘선택한 창’은 패널을 열기 직전 활성화한 SSH 터미널이다.
- ‘현재 탭 전체’는 그 작업 탭의 연결된 SSH 세션 목록을 클릭 시점에 고정한다.
- 각 세션에 한 번만 전달한다. 연결 실패·미지원 붙여넣기 대상은 개별 결과로 표시한다.
- 키보드 동시 입력은 별도의 명시적 모드이며 스니펫 일괄 붙여넣기가 이를 켜지 않는다.
- 앱의 입력 대상 선택을 바꿔도 다른 탭·장치·창으로 대상이 확대되지 않는다.

### 파일 전송

- 좌우 패널은 연결·경로·선택 항목을 독립적으로 유지한다.
- 서버 간 복사는 앱을 경유하므로 앱이 실행 중이고 양쪽에 접속 가능한 동안 진행한다.
- 취소·끊김·권한 부족·임시 파일 이름 변경 실패를 구분해 표시한다.
- 같은 파일로의 복사, 폴더를 자기 하위로 복사, 재귀 링크 순환은 전송 전에 차단한다.

### 파일 내보내기·가져오기

1. 기존 기기의 ‘설정 → 내보내기’에서 호스트·스니펫·설정 등을 파일로 저장한다.
2. 사용자가 해당 파일을 다른 Windows 또는 Mac 기기로 옮긴다.
3. 새 기기의 ‘설정 → 가져오기’에서 파일을 선택하고 항목·중복 처리 결과를 미리 확인한다.
4. 가져오기를 적용해 설정을 복원한다. 서버 연결은 사용자가 직접 시작한다.

- 기본 내보내기는 포맷 버전을 포함한 Passport JSON이며 비밀번호·개인 키 등 비밀값은 제외한다.
- 비밀값 포함을 선택하면 별도 암호로 보호한 패키지로 저장한다.
- 기기에 없는 로컬 경로·키 파일 경로는 다시 지정하고, 설치되지 않은 폰트는 기본 글꼴로 대체해 안내한다.
- 파일 내보내기·가져오기는 사용자 조작으로만 수행하며 자동 로컬 백업과 구분한다.
- OS에 종속된 암호화 비밀값을 그대로 복사해 다른 기기에서 쓸 수 있다고 가정하지 않는다.
- 이식용 비밀 포함 백업은 복호화한 값을 별도 암호 기반 패키지로 다시 암호화하며, 복원 후 새 기기의 보호 저장 방식으로 저장한다.
- 비밀값을 포함한 내보내기 패키지는 표준 암호 라이브러리의 scrypt와 AES-256-GCM을 사용하고, 포맷 버전·무작위 salt/nonce·인증 태그를 포함한다. 패키지를 여는 암호는 파일 안에 저장하지 않는다.

## 기술 선정과 구현 경계

Electron은 Chromium과 Node.js를 기반으로 하고 Windows·Mac용 바이너리를 제공한다. [Electron 공식 설명과 플랫폼 지원](https://github.com/electron/electron#platform-support)
SSH·파일 전송과 같은 Node 라이브러리를 활용하면서 두 OS의 화면 렌더링 차이를 줄이는 선택으로 판단했다.
패키지 크기·메모리 사용량은 측정 대상이며, 이 프로젝트에서는 터미널·분할·입력 동작의 일관성을 우선한다.

정확한 패치 버전은 설치 시점의 확인 작업이며, 제품 결정을 다시 사용자에게 요구할 미정 항목으로 두지 않는다.

- 화면 렌더러: React·xterm.js, Node 직접 접근 차단.
- preload/IPC: 정의된 메시지와 타입·대상 세션·호출 권한 검증.
- 세션/전송 관리자: SSH·SFTP·FTP·PTY 수명과 제한된 출력 버퍼 관리.
- 저장 관리자: SQLite·safeStorage·내보내기. 비밀값은 화면 상태·일반 로그에 넣지 않는다.
- 프로세스 종료와 창 이동을 구분한다. 다중 창에서도 세션을 하나의 관리 주체가 소유한다.
- context isolation·sandbox·CSP를 적용하고 임의 원격 웹페이지를 앱 권한으로 실행하지 않는다. [Electron 보안 문서](https://www.electronjs.org/docs/latest/tutorial/security)

## 검증 목표와 배포 조건

### 기능·호환성

- Windows 11 x64, macOS 14 이상 Apple Silicon에서 빌드·설치·실행한다.
- GUI·한글 입력·클립보드·파일 대화상자·드래그앤드롭은 각 OS의 실제 GUI 환경에서 확인한다.
- OS 표시 언어와 관계없이 앱 UI가 한국어로 표시되고 원격 출력과 사용자 데이터는 원문을 유지하는지 확인한다.
- 다크·라이트 외형, 1024×680과 1440×900 창, OS 배율 100%·150%·200%에서 탭·패널·버튼 잘림과 대비·포커스·입력 대상을 확인한다.
- 12개 터미널 테마에서 ANSI 16색·256색·트루컬러, 한글·넓은 문자, 긴 줄·리사이즈, 활성·비활성 커서, 선택·검색·복사 원문을 확인한다. v0.2의 4종 출력 강조 프리셋은 테마 조합, IP·로그 오탐, 행 배경 대비, 서버 색상 우선, 대체 화면 제외와 출력 부하를 별도로 검증한다.
- 일반 OpenSSH 서버와 Alpine·Ubuntu·Rocky 계열의 sh/bash/zsh를 시험 대상으로 둔다.
- 첨부 화면의 구형 CentOS 계열은 별도 호환성 항목으로 관리한다. 알고리즘 협상 결과와 실제 동작을 기록하고 지원 범위를 발표한다.
- 비밀번호·암호화 키, 호스트 키 등록·변경, FTPS 인증서 실패, 연결 끊김을 확인한다.
- FTP는 passive, FTPS는 명시적 TLS로 시험하고 접속 설정을 자동으로 다른 프로토콜로 바꾸지 않는다.
- 3분할 구성·분할 탭 이동·크기 조절·집중 보기·탭 분리 중 세션 유지와 입력 대상 정확성을 확인한다.
- 스니펫 대상 1개/작업 탭 전체, 다른 탭 제외, 끝 줄바꿈과 다중 줄·미지원 대상 처리를 확인한다.
- 한글·공백·긴 파일명, 대소문자 충돌, 링크 순환, 전송 실패·취소·덮어쓰기와 백업 복원을 확인한다.
- 파일 컨텍스트 메뉴의 단일·다중·빈 공간 선택, 반대편 복사 경로, 연결 끊김·경로 변경, 권한 변경 성공·거절, 삭제 확인, 메뉴 가장자리 배치와 두 OS의 키보드 접근을 확인한다.
- Windows↔macOS 파일 내보내기·가져오기, 비밀값 기본 제외, 암호화 패키지 복원, 중복 처리, 기기별 경로·폰트 차이를 확인한다.
- v0.2의 창 간 이동에서는 터미널 버퍼·연결 유지, 로컬 셸의 크기 변경·종료를 별도 확인한다.

### 성능 목표

최소 4코어·16GB RAM·SSD를 시험 기준으로 삼는다. Apple Silicon의 실제 측정 결과와 남은 플랫폼 검증은 [검증 기록](verification.md)에 기록한다.

- 호스트 500개 목록의 검색·필터·스크롤을 끊김 없이 처리한다.
- SSH 터미널 최대 32개, 한 작업 탭 16분할을 열 수 있도록 한다.
- 16개 세션에서 각각 초당 100KB 출력을 10분간 처리하며 입력 반응 지연 p95 100ms 이내를 목표로 한다. 네트워크 지연은 별도로 측정한다.
- 터미널당 기본 스크롤백은 10,000줄이며, 출력 큐에 상한과 흐름 제어를 둔다.
- 4GB 파일과 작은 파일 10,000개가 포함된 폴더를 시험한다. 파일 크기에 비례해 앱 메모리가 증가하지 않아야 한다.
- 창 닫기·세션 종료·전송 취소 후 핸들·연결·버퍼가 해제되는지 확인한다.

### 배포

개인 테스트용 산출물과 공개 배포 산출물의 상태를 구분한다.
서명용 계정·인증서가 없는 상태에서 서명·공증 완료를 주장하지 않는다.
정식 공개 배포를 추진할 때 서명·공증·설치 검증을 완료하고 필요한 비용과 공개 동작을 승인받는다.
현재 작업에는 계정 개설·비용 지출·공개 배포를 포함하지 않는다.
